## 今天评审批注：最近时间段

- 用户希望当前专注卡片展示最近已结束的时间段。评审稿新增同任务最近两段（倒序）与今日累计；示例 20 + 34 + 当前 42 = 96 分钟。当前计时与累计都保留，原生实现待推进。
- 现有代码：开始任务会把对应 session 置于主卡片，其他 session 不自动停止，仍在次级会话中。主卡片表示当前关注，不表示任务优先级。
- 现有代码：结束时间段记录结束时刻，移出活动会话，保留执行记录；任务不会因此标记完成，之后可重新开始。
- 现有累计口径是同任务今日有效执行时间，暂停间隔不计入；跨天总用时和最近已结束时间段尚未在主卡片显示。
- 建议文案将停止方块说明为“结束本段”，避免与任务完成混淆；这里只记录建议，未变更原生行为。

未运行任务累计用时评审：同步方案任务显示“累计 1小时20分 · 今日 20分”（示例数据）。累计定义为该任务跨天实际执行时长，不含暂停；应在未选中状态也可见。这是待实施设计，现有原生流只在选中/关注任务时显示今日已记录时长。切换主卡片仅改变关注会话，旧任务仍在流中且继续计时；现有“现在”标记取决于关注任务，不能代表所有运行会话，后续应将运行状态与关注状态分开呈现。

## 最新评审决定：执行中 / 规划中

下方任务流拆分为上下两组：上组执行中（所有正在计时的任务，不仅主卡片），下组规划中（暂停、未开始、结束本段后尚未完成）。两组均直接显示跨天累计与今日实际用时；执行中额外显示本段计时，暂停保留最近结束段并提供继续。开始/继续移入执行中，暂停/结束本段移入规划中，完成进入独立折叠历史入口。主卡片表示关注会话，切换关注不改变其他会话计时。已完成记录保留，不归入规划中。

评审画布加长以展示分组全貌，原生页面应以滚动内容区和固定底栏呈现。仅修改静态评审稿，原生实现待推进。

## 最新评审批注：简化计时操作（替代前述暂停/结束双入口方案）

- “规划中”更名为“今日规划”。
- 主卡片大数字保留本段计时，右侧仅留跨天累计用时，移除最近时间段与重复今日汇总；任务列表仍保留累计/今日明细。
- 暂停：关闭并保存本段执行时间，任务移回今日规划；继续时建立新的计时段，历史累计不清零。
- 完成：保存当前执行段并标记任务完成，移入已完成；使用“✓ 完成”明确文案，不再用停止方块。建议提供完成后的撤销入口；撤销恢复未完成但不自动开始计时。
- 这是本轮评审方案，原生代码尚未修改。旧实现暂停保留可恢复会话，停止关闭会话且不标记完成；新设计将这一区别从用户操作中移除。

## 最新评审决定：主卡片与执行队列

此条覆盖上文主卡片在执行中重复显示、已完成另行折叠的旧方案。主卡片与执行队列互斥展示。暂停或完成主卡片任务时保存本段，随后将队列最上方条目提升为主卡片，同时从队列移除；提升仅切换展示，不重启计时、不重复创建时间段。队列为空则主卡片为空闲。暂停任务回到今日规划待继续；完成任务留在今日规划显示完成状态、累计用时，不单设完成分组。今日规划按任务身份更新，避免重复插入。

主卡片删除“从 19:56”，右侧显示同任务跨天累计和今日总用时；大数字保留本段用时。仅更新评审稿，原生实现尚未改动。

### 用户确认的结构修订

今天不设日历入口；未来日历归任务的时间视图。手动新增与重复规则生成的当日规划共用同一领域结构、卡片、状态、执行记录、comment 与账单关联；来源只作为可选元数据，用于规则追溯和生成去重，不分两套列表或操作。修改当天实例不隐式修改规则。今日示例同时展示规则早餐/通勤与手动演示材料，不显示来源标签。此处为评审设计，尚未实现原生业务。

### 补充后的领域与交互契约

- 重复规则只负责生成；进入某一天后统一成为同一种当日实例。优先扩展现有 `V2PlanItem`，避免建立第二套任务对象。
- 同一规则同一本地日期使用幂等生成键去重；暂停规则只影响未来未生成日期，单日例外只改当天。
- 当天实例的完成 / 今天未完成 / 恢复都只影响当天。`今天未完成` 与暂停规则是两个不同操作。
- comment 与实际值可以先保存，不要求完成；完成也不要求记账。预计金额不会自动入账。
- “完成并记账”只在账单草稿已经可确认时作为一次动作出现；若记账失败，保留任务完成并把账单留在待处理状态。
- 新增阅读示例说明无金额路径：计划 1 页、实际 3 页、可写 comment，不显示任何记账控件。
- 新增跨天示例：周五早餐未完成不污染周一的新实例；9/21 阅读完成后，9/22 仍生成目标 1 页的新实例，今日用时重新从 0 开始。
- 完成 / 未完成详情默认折叠，主要操作按约 44pt 触控面积设计；这些仍是静态设计稿，不能替代原生交互验收。

## 倒树设计提案（2026-09-21）
