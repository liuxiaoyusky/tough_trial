# Tough Trial 插件（版本 1 / 2）

在应用顶部打开「功能与插件」，选择「从文件安装插件」，选中 JSON 文件并核对能力后安装。示例：`reading-note.json`。

当前框架包括内置模块注册、依赖关系、持久化启停，以及声明式表单插件。表单输出经过契约校验后，调用与随手记相同的保存命令。关闭模块保留数据；重新打开后继续使用。内置模块仍随 App 编译分发。

这不是 Obsidian JavaScript 插件运行时，不加载任意脚本或原生动态库。版本 1 的外部插件只能提供表单、文本模板和用户点击后打开的 HTTPS 链接。

字段：

- `schemaVersion`: 固定为 1。
- `id`: 以 `community.` 开头的小写字母、数字、点和连字符，不超过 100 字符。
- `name` / `summary`: 展示名称与说明。
- `fields`: 最多 20 个字段，每个含 `id`、`title`、`required`。
- `template`: 使用 `{{字段ID}}` 引用输入，单次替换，保留用户输入的原文。
- `link`: 可选 HTTPS 链接，不允许嵌入账号凭据。

单个插件文件不超过 64 KiB。未知顶层能力、版本不匹配、重复字段、未声明的占位符会被拒绝。最多保存 50 个插件。同 ID 再次安装会在用户确认后更新模板，已保存记录不改变。

开启使用记录时，保存会产生本地 Trace 元数据；正文、文件内容和凭据不写入 Usage Trace。停用 Trace 不影响业务回执。

## 版本 2

版本 2 使用 `manifestVersion: 2`，与业务数据的 `schemaVersion` 分开。完整示例见 `reading-note-v2.json`。顶层字段如下：

- `id` / `version` / `hostAPIMajor` / `name` / `kind`: 插件身份、语义版本、宿主 API 主版本和声明式包类型。
- `permissions`: 精确的能力与范围。当前支持 `capture.create` + `submitted-form`，以及与声明的 HTTPS 域名一一对应的 `link.open`。
- `contributions.forms`: 宿主表单、字段类型和 `submit` 命令。第一阶段命令固定为 `core.capture.create`。
- `contributions.links`: 用户主动点击的 HTTPS 链接；不支持 App scheme、网络请求、脚本、SQL、迁移文件或任意原生页面。

模板只能使用已声明字段的 `{{fieldID}}`，只做一次替换。未知字段、未知顶层或嵌套键、重复 ID、未来宿主版本、不安全链接和新增执行器都会拒绝。单个包不超过 64 KiB，最多安装 50 个。

安装或更新会先展示新增/移除的能力和链接域名。能力范围不变的更新复用原授权；新增范围必须由用户在安装页明确确认，不能静默继承。更新不能降级版本，清单和授权以一个原子包记录保存。卸载只移除定义、偏好和授权，已生成的随手记、附件和历史引用保留，并在管理页显示保留记录。

缺失或与当前包不一致的授权不会作为更新的授权依据，必须重新确认。清单损坏、ID 冲突或授权版本异常时保留原文件并阻止覆盖。点击关联链接时也由宿主即时校验；旧页面不会在停用、升级后继续沿用失效授权。

表单不会持有完整 `V2AppStore`。宿主创建带有插件 ID、表单 ID、操作 ID 和模块 generation 的受限上下文；在 Capture 提交前校验授权、grant revision 和 generation，再调用 Capture 命令。提交成功后不再用过期 generation 把已写入的结果误报为失败；同一表单提交的宿主操作 ID 会让重试重新找到同一条 Capture，避免重复写入；重新打开表单是新的提交，相同正文也允许再次记录。停用期间返回的旧表单结果不会写入。Trace 只记录模块、命令、操作 ID 和字数等元数据，不记录表单正文、文件内容或凭据。

`V2FieldDefinition` 和 `V2TypedFieldValue` 为宿主登记的扩展字段提供稳定命名空间。值只允许 `text`、`decimal`、`boolean`、`date`、`enumID`、`recordRef`；未知字段、停用字段、类型不匹配或不符合枚举/日期/数值约束的输入会拒绝。字段停用后历史值由宿主保留为只读，ID 不复用。

版本 1 的文件仍按原语义导入，不能在 v1 文件里偷偷加入 v2 字段。版本 1 与版本 2 的同 ID 不能互相覆盖，避免旧包绕过新权限模型。

## 运行时与后续边界

参见 [插件运行框架与统一数据契约](../superpowers/specs/2026-09-10-plugin-runtime-and-contracts-design-zh.md)。原生模块、声明式包与未来脚本执行器的边界分别定义。

当前运行时将“页面显示”和“功能开关”分开；停用 Capture 会暂停声明式表单的保存能力，保留表单配置与既有内容。Finance / Budget 仅依赖 Ledger，可从功能管理页面独立打开；理账与笔记也有独立入口，不依赖 Capture 页面。未知 ID 不会自动获得执行能力。旧版隐式暂停的功能升级后保留暂停状态，需要在管理页面点击恢复。

现有原生模块已接入统一命令与生命周期；声明式包仍只保存随手记，不能调用支付确认，也不会直接生成财务计划。AI 动态工具目录由受信任的原生模块提供，第三方包不能改写工具策略或系统提示词。新增业务领域的跨设备同步和二进制附件传输仍属于独立协议阶段。
