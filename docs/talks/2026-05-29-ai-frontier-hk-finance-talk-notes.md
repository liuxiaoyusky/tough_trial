# 2026 AI 前沿趋势 + 香港金融业发展分享

状态：讨论存档 v0.1
日期：2026-05-29
用途：记录截至目前的共同认知、案例线索和后续待展开问题。本文不是正式文章定稿，后续继续迭代。

## 一句话主旨

AI 时代真正的机会，不只是“会用大模型”，而是会把大模型放进正确的边界里。

大模型本身是一种泛化能力。Chatbot、Agent、MCP、plugins、skills、workflow、approval、logs、checkpoint 这些应用形态和工程机制，本质上都是在给这种泛化能力加边界：让一个基础能力很强、但责任感和场景感不稳定的系统，进入具体行业、具体流程、具体岗位之后，变得可用、可控、可复核。

chatbot 时代，AI 主要是“说错”。应对方式是设计更清楚的 prompt 和上下文 context，让模型少猜、少编、少偏离。

agent / coding agent / tool-use 时代，AI 开始能看文件、改代码、调工具、进消息入口、执行多步骤任务。AI 不只是回答问题，而是开始接触真实工作流。

一旦 AI 开始做事，核心问题就从“怎么让它说得更好”，变成“它能看什么、能改什么、何时停、谁复核、怎么回滚、谁负责”。于是，针对 agent 的 harness engineering 应运而生，也就是 Claude Code、Codex、OpenClaw、Hermes 这些产品反复在解决的问题。

一句话说：

> chatbot 时代，我们主要管理 AI 的表达；agent 时代，我们开始管理 AI 的行动。

## 核心开场：AI 是一个喝醉的实习生

“喝醉的实习生”不是说 AI 笨，而是把 AI 的两个关键特征分开：

- “喝醉”代表责任意识浅薄、莽撞，且可能夹杂幻觉。它会认真完成任务，但不会真正承担后果；它会把不确定的东西说得很像真的。
- “实习生”代表基础能力很强，但没有业务先验。它会读、会写、会总结、会模仿、会生成方案，但不知道具体行业、机构、客户、监管、审美、偏好和风险边界。

因此，使用 AI 的第一原则不是“让它多做”，而是“多明确，少猜”。

需要明确：

- 任务：到底是研究、草稿、判断、执行，还是复核？
- 标准：什么叫好？准确、保守、便宜、快速、合规、可解释，哪个优先？
- 上下文：行业、地区、客户、法规、机构偏好是什么？
- 权限：它能看什么、能改什么、能不能对外行动？
- 责任：最终由谁判断、谁签字、谁承担后果？

## 两个解释性例子

### 例子一：盲人过马路

如果一个盲人要过马路，我们会选择训练有素的导盲犬，还是世界上最好的 AI 模型？

这个例子说明：能力不能脱离场景评价。

“世界上最好的 AI 模型”可能在语言、代码、知识和推理上远强于导盲犬，但过马路需要的是实时环境感知、身体位置判断、交通风险训练、稳定保守的反应，以及长期形成的人与导盲犬之间的行动协议。

所以导盲犬胜出，不是因为它更“聪明”，而是因为它在这个任务上的能力形态更匹配，责任边界更清晰，失败模式更可理解。

结论：AI 能力强，不等于适合进入所有任务。任务匹配度比模型排名更重要。

### 例子二：最好的 AI 大模型是什么

“我订阅了我觉得最好的一个 AI 大模型，有人知道是什么吗？”

如果不补充标准，任何回答都只是在猜。所谓“最好”可能指推理最好、中文最好、写作最好、编程最好、便宜最好、香港可访问最好、数据隐私最好、和 X 信息流结合最好，或者最近资本和产品事件最值得讲。

当条件逐步收窄为“海外的”“香港可以访问的海外模型”“最近和 X/xAI 收购整合相关的”，答案才可能指向 Grok。

这个例子服务于同一个心法：你的判断标准不一定是我的判断标准，你的审美不一定是我的审美。多明确，少猜。

## Harness 的本质：不是释放模型，而是约束模型

基于“喝醉的实习生”这个基本认知，chatbot、agent、MCP、plugins、skills、workflow 这些东西不是为了单纯释放大模型，而是为了约束大模型，确定边界，从而聚焦。

- Chatbot 主要约束表达边界：它说什么，但不直接做什么。
- Agent 主要约束行动边界：它能做什么，做到哪一步必须停下来。
- MCP 主要约束工具和上下文边界：模型通过什么标准接口接触真实世界。
- Workflow 主要约束过程边界：固定步骤、人工复核点、失败处理、回滚路径。
- Skills/plugins 主要约束能力边界：把经验、工具和流程沉淀成可复用模块。

约束不是削弱能力。约束的意义是把一个泛化、莽撞、容易幻觉的系统，压进一个可用、可控、可验证的工作场景里。

## AI 机会：边界工程是一条高门槛但可循序渐进的路

AI 时代真正稀缺的机会，不是“会用大模型”，而是会把大模型关进正确的边界里。

这是一种交叉能力：

- 懂模型：知道 LLM 擅长什么、会错在哪里。
- 懂业务：知道真实流程里哪些环节有价值，哪些地方不能碰。
- 懂权限：知道数据、工具、操作、审批怎么分层。
- 懂产品：知道怎么让人愿意用，而不是堆功能。
- 懂评估：知道怎样判断它真的变好了，而不是 demo 看起来很酷。
- 懂组织：知道 AI 不是一个按钮，而是工作方式重组。

但这不是说必须掌握所有能力才有机会。它是一条成长路线：

1. 会把需求说清楚，就已经比普通用户强。
2. 会设计 prompt 和 workflow，就能提升自己和小团队效率。
3. 会接工具、做 MCP、做 agent，就开始形成可复用生产力。
4. 会做权限、日志、评估、回滚，就开始进入企业级机会。
5. 会结合行业流程，就不再只是 AI 爱好者，而是能卖解决方案的人。

只要在这条路上比同领域的人跑得快一点，就可以创造价值，甚至挣到钱。

## 时间线：Claude Code 到 OpenClaw 到 Hermes

这条线不是底层智能的一次次跃迁，而是 AI 应用形态的一次次成熟。

### Claude Code：开发者先跑起来

去年 Claude Code 已经在开发者手里大量普及。开发者用它做代码、写自媒体、写文章、整理笔记、处理文档等行为已经很成熟。

Claude Code 的优势在于代码仓库这个场景天然边界清楚：

- 工作空间是 repo。
- 任务是 issue、bug、feature、文档或重构。
- 验证是 tests、build、lint、diff。
- 回滚是 git。
- 审计是 commit、review、terminal logs。

所以它先在开发者里普及，不是偶然。开发者本来就习惯定义任务、检查输出、处理错误、管理版本和权限。

### OpenClaw：入口革命

OpenClaw 的破圈点，不是让 AI 本身更聪明，而是把 AI 从一个黑黝黝的 terminal 搬进了普通人熟悉的聊天框、移动端、语音和生活入口。

它降低的是接触门槛，不是使用门槛。

- 接触门槛：我在哪儿遇到 AI？Terminal 还是 Telegram、WhatsApp、iMessage、Slack、Discord？
- 使用门槛：我会不会定义任务、给上下文、设边界、验结果？

OpenClaw 让普通人离 AI 更近，但 AI 本身的使用门槛没有消失。用户仍然要知道怎么提需求、怎么判断结果、什么时候让它停、哪些权限不能给、出错以后怎么恢复。

用“喝醉的实习生”的比喻：

OpenClaw 不是让实习生更清醒了，而是把这个喝醉的实习生带到了你的客厅、手机、群聊、工作频道里，并给了他更多钥匙。

它的突破是入口革命；它的不足是管理缺位。普通人离 AI 更近了，但还没有变成 AI 的合格 manager。

### Hermes：管理层补强

Hermes 并不一定在单项能力上明显优于 OpenClaw。Hermes 能做的，OpenClaw 打 plugin 也可能做；OpenClaw 能做的，Claude Code 加 plugins、skills、MCP、scripts、cron、messaging bridge 也可能做。

差别不在“理论上能不能做”，而在：

- 默认有没有做好。
- 安装配置是否顺。
- 能力是否被组织成产品心智。
- 用户是否知道该怎么调用。
- 权限、日志、回滚、审批是否内建。
- 是否有一套持续使用的工作流。

Hermes 强化的是“管理 AI 的中间层”。它把 goal、skills、memory、session search、curator、kanban、subagents、approval、logs、provider switching、checkpoint、MCP catalog 等能力组织成一种产品叙事：

我不是在和一个模型聊天，我是在管理一个可以积累、分工、复盘、被调度的工作系统。

用“喝醉的实习生”的比喻：

- Claude Code 是让开发者在代码仓库里管理这个实习生。
- OpenClaw 是把实习生接入你的生活入口。
- Hermes 是尝试给这个实习生配任务清单、工作手册、记忆库、审批按钮、复盘机制和小组协作系统。

## 关键判断：不是技术更新，而是应用成熟

CC → OpenClaw → Hermes，不是底层智能的一次次跃迁，而是 harness 层逐渐产品化。

技术上可实现，不等于用户会使用。用户会配置，不等于会持续使用。能力存在，不等于形成生产力。

AI 产品成熟的标志，不是又多接了一个模型，而是把一堆“理论上可组合”的能力，做成用户自然会走的默认路径。

默认路径就是产品价值。

## 这个案例给金融业的启发

金融业不一定需要最炫的 agent。金融业需要的是可控的智能工作流。

金融业的 AI 机会，不在于追求完全自动化，而在于把已有模型接进已有流程：

- 把已有知识库变成可检索上下文。
- 把已有审批变成 AI action gate。
- 把已有权限体系接进 agent identity。
- 把已有审计日志覆盖到 AI 工具调用。
- 把已有工作流变成半自动智能流程。
- 把文本化、流程化、可复核的认知劳动重新组织起来。

金融业需要的是：

- 可审计：每一步工具调用、输入输出、上下文来源都要留痕。
- 可解释：不只是给答案，而是说明基于什么证据、为什么采取这个动作。
- 可授权：不同任务、用户、数据源、系统操作有不同权限。
- 可回滚：文件、配置、流程状态能恢复；外部动作要有确认门。
- 可问责：谁给的指令，谁批准的动作，谁承担最终判断。
- 可证明没有越权：通过 sandbox、allowlist、policy、logs、replay 来证明。

换句话说，金融业 AI 机会不是造一个更聪明的大脑，而是把喝醉的实习生放进一套成熟的办公室制度里。

## 第二主题：从 AI 擅长的能力出发寻找业务机会

前一个主题讨论的是：怎么让人 + AI 把一件事做成产品，也就是如何通过边界、权限、流程和复核，把 AI 变成可控生产力。

第二个主题讨论的是：怎么发现有什么事情可以被 AI 重新定义，而不只是用 AI 替代人工来节省成本。

当前共识：

- 不要先问“哪个岗位可以被 AI 替代”。
- 要先问“AI 擅长的能力，如果成本下降 10 倍、100 倍，哪些过去太碎、太慢、太贵、太依赖专家的事情会第一次值得被产品化？”
- 真正的新机会，往往不是原来有人做、现在换机器做，而是原来一直有需求，但因为理解、解释、跟进和个性化成本太高，所以没人认真做。

一句话表达：

AI 重新定义行业的地方，通常不是简单替代人工，而是把过去太贵、太慢、太碎、太难个性化的认知能力，变成可以持续运行的产品和基础设施。

### AI 擅长的五类能力

| AI 能力 | 业务里的旧痛点 | 机会识别问题 |
|---|---|---|
| 理解非结构化信息 | 信息散在文档、聊天、图片、录音、邮件、网页里，系统看不懂 | 这个行业里有哪些“人能看懂、系统看不懂”的信息？ |
| 生成结构化表达 | 很多人懂事情，但写报告、memo、邮件、说明、narrative 很耗时 | 哪些工作卡在“理解之后要写出来”？ |
| 比较、归纳和发现变化 | 信息源太多、版本太多、时间跨度太长，人无法持续追踪 | 哪些变化过去只能靠人偶然发现？ |
| 个性化解释 | 专家服务太贵，只能覆盖少数客户或高价值场景 | 哪些解释服务过去只给少数人，现在可以低成本覆盖更多人？ |
| 多步骤流程编排 | 流程长、状态多、跨系统协作难，需要人持续盯进度 | 哪些流程不是难在单点判断，而是难在持续推进？ |

这五类能力可以作为寻找 AI 机会的扫描仪。看到一个行业时，先不要问“做一个什么 AI app”，而是问：这个行业里哪些旧痛点正好对应这些能力。

### 金融场景细分

| AI 能力 | 金融旧痛点 | 可能被重塑的场景 |
|---|---|---|
| 理解非结构化信息 | 投研材料、监管文件、客户沟通、KYC/AML 材料太碎，很多信息只能靠人读和记 | 投研知识库、合规知识库、客服/投诉洞察、KYC/尽调材料整理 |
| 生成结构化表达 | memo、screening report、客户解释、case narrative、管理层汇报都很耗时 | Screening report、投研 memo 草稿、RM 客户跟进草稿、AML/KYC case narrative、合规/风控汇报 |
| 比较、归纳和发现变化 | 财报、earning calls、公告、监管规则、产品材料持续变化，人很难长期追踪 | Earnings call 对比、公司公告追踪、产品材料一致性检查、监管变化映射、市场观点雷达 |
| 个性化解释 | 个性化解释和持续服务太贵，通常只能给高净值客户或重点客户 | 客户组合变化说明、市场事件个性化解释、投资教育、产品风险解释、RM 跟进建议 |
| 多步骤流程编排 | 开户、投后监控、投诉处理、审批准备等流程长且状态多 | 新客户开户材料检查、监管变更处理流程、投后监控流程、客户投诉处理、内部审批包准备 |

几个适合演讲展开的金融例子：

- 投研知识库：把 earnings calls、年报、公告、研报、自媒体观点等多源材料整理成可搜索、可对比、可追踪的研究资产。重点不是“少读几份报告”，而是机构第一次可以系统性复用自己的投研记忆。
- Screening report：从只筛财务指标，升级到结合新闻、管理层表态、市场观点、风险叙事，生成“为什么值得看”的解释。重点是从筛数字，变成筛变化、筛故事、筛证据。
- 客户解释服务：同一个市场事件，对不同风险偏好、持仓结构、理解水平的客户，可以生成不同解释草稿。重点不是 AI 直接卖产品，而是让更多客户听得懂“这件事和我有什么关系”。
- 监管/合规映射：新规发布后，AI 先判断可能影响哪些业务、产品、话术和流程，再交给合规人员确认。重点是合规从事后检查，前移到流程设计和前线提醒。
- 客服/投诉洞察：客户问题不再只是单个工单，而是能被归类、聚合、识别趋势，反向喂给产品、运营和合规。重点是客服从成本中心变成实时反馈系统。

### 生活场景延伸

生活场景可以用来说明：这套方法不只适用于金融业，各行各业和个人生活都有被 AI 重塑的机会。

| AI 能力 | 生活旧痛点 | 可能被重塑的场景 |
|---|---|---|
| 理解非结构化信息 | 通知、截图、账单、合同、医疗报告、家庭群消息太散 | 家庭信息 inbox、个人文档管家、医疗资料整理、消费记录解释、家庭事务助手 |
| 生成结构化表达 | 投诉、申请、请假、租房沟通、理赔说明、家校沟通让人有压力 | 表达代理、行政材料助手、家校沟通助手、求职沟通助手、理赔说明助手 |
| 比较、归纳和发现变化 | 租房、保险、课程、旅行、家电、信用卡、手机套餐选择太多 | 个人采购研究员、租房/买房筛选助手、保险/套餐解释器、家庭决策助手 |
| 个性化解释 | 通用建议没用，真人陪伴和咨询太贵 | 学习陪练、健康习惯教练、亲子学习助手、个人财务解释、情绪整理助手 |
| 多步骤流程编排 | 搬家、旅行、就医、报税、留学、装修、理赔流程长且状态多 | 搬家 agent、旅行 agent、就医 agent、理赔 agent、家庭运营 agent |

生活类 AI 产品的机会，不是把一个 app 加上聊天框，而是找出那些人类一直想有人帮忙、但过去请不起、找不到、懒得做、无法持续做的事情。

### 跨行业重塑的判断框架

同一套方法可以迁移到其他行业：

| 行业 | 过去为什么做不好 | AI 让什么变便宜 | 可能的新产品形态 |
|---|---|---|---|
| 医疗健康 | 病历、检查、用药、问诊记录分散，患者说不清楚 | 病情整理、报告解释、长期追踪 | 就医前摘要、慢病管理、复诊问题清单 |
| 教育 | 个性化反馈太贵，老师无法持续服务每个学生 | 错误归因、不同解释、练习生成 | 学习陪练、作业反馈、家长学习报告 |
| 法律 | 阅读材料、找条款、整理事实、写初稿成本高 | 材料摘要、合同对比、文书草稿 | 合同审阅助手、案卷整理、法规提醒 |
| 地产 | 决策因素太多，房源信息和个人生活偏好难匹配 | 房源比较、合同解释、偏好匹配 | 租房/买房筛选助手、装修流程 agent |
| 零售消费 | 商品太多、评论太乱、需求难表达 | 评论总结、偏好匹配、选项比较 | 个人采购研究员、售后/退换货助手 |
| 制造供应链 | 质检、设备、维修、供应商记录分散，经验难复用 | 异常归因、经验沉淀、风险提醒 | 质检异常助手、维修知识库、供应商风险监控 |
| 招聘和组织管理 | JD、简历、面试反馈、培训记录难系统复盘 | 反馈结构化、问题生成、路径建议 | JD 校准、面试反馈助手、培训路径建议 |
| 政府和公共服务 | 政策难懂、表格复杂、申请流程长 | 政策解释、材料清单、表格草稿 | 福利申请助手、公共服务解释器 |
| 内容和媒体 | 难在选题、资料整理、观点比较、持续更新 | 资料整理、观点地图、多版本表达 | 选题雷达、采访整理、事实核查清单 |

收束观点：

AI 重塑行业的地方，往往不是原来有人做、现在换机器做；而是原来大家都需要，但因为太贵、太慢、太碎、太难个性化，所以一直没人认真做。当 AI 把理解、表达、比较、个性化解释和流程编排的成本打下来，新产品就会出现。

## 第三主题：结果前置的 AI 学习路径

前两个主题分别讨论了：

- 怎么把人 + AI 管成一个可靠的生产系统。
- 怎么从 AI 擅长的能力出发，发现哪些事情会被重新定义。

第三个主题要落到个人成长：普通人怎么进入 AI 时代的学习循环。

当前共识：

- AI 时代的学习不是“少学习”，而是“学习顺序变了”。
- 过去是先学知识、再做项目、最后得到结果。
- 现在可以先定义一个真实结果，让 AI 生成第一版，再从结果倒推自己缺什么。
- 这是一种结果前置的 reverse engineering 学习法。
- 人和 AI 的差异，不只是“谁更聪明”，而是谁在玩有限游戏，谁在继续无限游戏。

一句话表达：

过去我们从知识走向结果。AI 时代，我们可以先拿到一个粗糙结果，再从结果倒推知识、结构、判断和能力。

### 学习循环：学 + 具体场景实战 + 复盘

AI 时代学习不是追课程、追工具、追模型排名，而是建立一个循环：

1. 学：先获得最小必要理解，不追求一口气学完。
2. 做：把知识放进一个具体场景里，用 AI 协作完成一个真实产出。
3. 复盘：看哪里做得不好，是需求没讲清楚、AI 没边界、工具不会用，还是自己没理解。
4. 再学：针对暴露出来的问题补课。
5. 重做：用新的理解推翻或改进上一版。

这个循环和传统学习路径的区别在于反馈更早。

传统路径：

> 学基础 -> 学工具 -> 做练习 -> 做项目 -> 得到结果

AI 时代路径：

> 定义结果 -> 让 AI 做出第一版 -> 拆解结果 -> 发现缺口 -> 补知识 -> 重做/改进结果

第一版不是作品，第一版是教材。AI 生成的第一版真正的价值，不是交付，而是帮你暴露：

- 你不会定义需求。
- 你不会判断质量。
- 你不知道行业标准。
- 你缺少审美参考。
- 你不了解实现原理。
- 你不知道怎么验收。

所以 AI 时代学习不是“更少学习”，而是“学习更精准”。

### 有限游戏与无限游戏：人类能力的方向

这个点可以作为第三主题的上位心法：为什么 AI 越强，人越不能只训练自己在有限任务里和 AI 比输赢。

人、AI、动物、工具的差别，不只是能力强弱，而是它们参与游戏的方式不同。

- 工具是人的被动延伸。工具本身不定义问题，不选择目标，也不承担后果。
- 动物有环境适应和训练能力，但通常在具体场景里行动。导盲犬不是比 AI 更聪明，而是在“带人安全过马路”这个有限任务里，能力形态、训练边界和失败模式更匹配。
- AI 会越来越像一个终极的有限游戏玩家。只要问题有目标、有规则、有反馈、有胜负标准，它就可以不断逼近更优解。
- 人更像无限游戏玩家。人会输掉很多具体游戏，但会继续改变规则、重组环境、延续意义、创造下一轮游戏。

可以这样讲：

> 人类一直在有限游戏里输，但一直在无限游戏里继续。

从海洋到陆地，从山洞被赶出来，从树上被赶到地上，乃至输给猛兽之后开始采集、种植、组织协作，人类并不是在每一场有限游戏里都赢。人类真正强的地方，是在失败之后还能重新定义问题：换环境、换工具、换组织方式、换生存策略，最后把一次失败变成下一轮文明演化的起点。

所以，未来 AI 可能会成为解决有限问题的终极玩家：写得更快、算得更准、检索更全、优化更强、执行更稳。但它不能替人解决那些没有唯一输赢标准的问题：

- 什么值得做？
- 我们要成为什么样的人或组织？
- 在效率、风险、自由、尊严、关系、意义之间怎么取舍？
- 当旧规则让人无路可走时，是否应该换规则？

这并不是说 AI 不能参与这些问题。AI 可以帮助我们整理事实、提出选项、模拟后果、暴露盲点。但最终决定游戏要不要继续、规则要不要改变、代价是否值得承担，仍然是人的问题。

这一点也决定了人和 AI 应该怎么协同：

- 不要把人的能力发展方向放在“比 AI 更会完成封闭任务”上。
- 要发展定义问题、选择目标、设定边界、判断代价、组织协作、复盘失败、重写规则的能力。
- AI 越强，人越应该把它放进有限游戏里做高强度求解；人自己则要负责判断哪些游戏值得玩、怎么玩、什么时候退出，以及如何开启下一局。

一句话版本：

> AI 会越来越擅长赢下有限游戏；人的价值在于决定游戏是否值得继续，以及在输掉一局之后还能不能创造下一局。

### Codex 的角色：进入学习循环的工具

Codex 不应该被讲成一个完整教程，也不应该被讲成“替你写代码的外包”。在这个演讲里，它更适合作为一个例子：

> Codex 是让普通人进入“结果前置 -> 拆解 -> 复盘 -> 重做”学习循环的工具。

你不需要先成为工程师，不需要先学完整前端课程，不需要先懂所有工具。你只需要先掌握用 Codex 进入循环的最少必要知识。

使用 Codex 的最少知识：

| 概念 | 最少理解 | 学习循环里的作用 |
|---|---|---|
| Project | 一个目标对应一个本地工作空间 | 不把所有事情混在一起，让 AI 在明确边界里工作 |
| Thread | 一次具体任务的对话和执行记录 | 一个 thread 只处理一个阶段，比如讨论目标、做计划、实现首页、复盘问题 |
| Plan | 先让 AI 说明准备做什么、为什么这样做、怎么验证 | 人管理 AI 的第一道边界 |
| Diff | AI 改了哪些文件、改了什么内容 | 不需要完全懂代码，但要看有没有改不该改的东西 |
| Run / Preview | 让结果跑起来或预览出来 | AI 说完成不等于完成，没有跑起来就不算完成 |
| Review | 人看结果，而不是只看 AI 的解释 | 判断结果是否符合目标、是否像模板、是否有明显问题 |
| Retrospective | 让 AI 复盘失败原因 | 把失败变成学习清单，而不是让 AI 道歉 |
| Redo | 带着复盘结果重做或迭代 | 重做不是失败，是学习路径的一部分 |

一句话版本：

> 用 Codex 学习，只需要先懂 8 个动作：建 Project、开 Thread、要 Plan、看 Diff、跑 Preview、做人类 Review、让 AI Retrospective、再 Redo。

### 例子：用个人网站进入 AI 学习循环

个人网站是一个适合作为演讲例子的项目，因为它足够小，但包含真实产品开发的完整链路：

- 需求
- 设计
- 内容
- 前端
- 部署
- 反馈
- 迭代

可以这样讲：

1. 我想做个人网站，但不先学完整前端。
2. 我先和 Codex 讨论目标：这个网站给谁看、想表达什么、像作品集/简历/博客还是个人品牌。
3. 让 Codex 给计划，不写代码：页面结构、内容模块、技术栈、验证方式。
4. 我看计划，问不懂的地方，删掉不需要的东西。
5. 让 Codex 做第一版。
6. 第一版大概率不好：像模板、内容空、设计俗、手机端差、部署失败。
7. 我让 Codex 复盘：为什么不像我？哪些设计决策是它自己猜的？我缺什么素材？我需要懂哪些基础？
8. 我补一点 HTML/CSS、内容结构、设计参考、部署知识或 git 基础。
9. 推倒重做第二版。

这个例子和前面的“喝醉的实习生”呼应：

- 如果你只会下命令，你得到的是一个喝醉实习生随手做的东西。
- 如果你会看计划、设边界、判断输出、复盘问题，你就开始学会管理它。
- 管理它的过程，反过来训练你的产品判断、技术理解和审美标准。

核心句：

> Codex 的正确学习方式，不是把它当外包，而是把它当一个可以快速生成“可批判对象”的学习工具。第一版让你看到结果，复盘让你看到缺口，下一版才真正让你成长。

### 最少网络知识

这一段要写得很轻。VPN 不是学习主题，只是进入 Codex 学习循环的基础连接条件。

对香港用户来说，Codex 有时可以直接连接，有时会受网络、公司防火墙、DNS、登录流程影响。新手不需要研究复杂网络，只要知道三件事：

1. Codex 需要稳定连接 OpenAI 服务。如果登录失败、请求超时、模型无响应，先不要怀疑自己不会用，先检查网络。
2. 浏览器 VPN 插件通常不够。Codex desktop app 和 Codex CLI 走的是系统/应用网络，不一定走浏览器插件。
3. 优先使用简单稳定的系统级 VPN app。香港用户可以准备 Surfshark 或 LetsVPN 作为备用方案。

这段不要讲成“必须翻墙才能学 AI”，而是讲成：

> 学习 AI 的第一步不是研究网络，而是确保工具能稳定连上。如果 Codex 登录或调用不稳定，先准备一个系统级 VPN，保证 desktop app 和 CLI 都能正常走网络。

注意事项：

- 先遵守所在公司、学校、地区的网络和数据政策。
- 不要在不可信 VPN 下处理公司机密、客户资料、金融敏感数据。
- 如果是公司网络，优先问 IT 是否允许使用 Codex、VPN、外部 AI 工具。
- 如果 Codex 失败，先区分是网络问题、账号问题、权限问题，还是 prompt/任务设计问题。
