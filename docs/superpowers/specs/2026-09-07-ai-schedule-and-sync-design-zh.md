# AI 驱动个人日程与 Markdown 同步

状态：用户已批准持续推进路线 1–5（2026-09-07）。本文替代旧规格中“所有日程写入必须逐次确认”的交互约定；语音已验收，本轮继续建设执行和同步能力。

## 产品目标与交互

移动端个人日程整理助手。聊天和语音是主要入口，今天、任务和回想用于执行、展示及微调。语音继续由用户点完成后提交。

用户明确要求的日程变更默认立刻执行，在聊天显示实际变更、相关任务高亮、整次撤销。设置可开启“修改前确认”；开启后必须显示具体变更再批准，取消不写入。纯讨论、只读问题、Dreaming 和信息不足时不得擅自修改。已有计划草稿入口兼容保留。

可执行整理覆盖：新增任务、父子拆解、备注中保留限制条件、排期/延期/取消排期、完成/恢复、归档。缺少日期不强造日期，可创建未排期任务；同名对象不能确定时追问。继续补充或改口应引用现有对象修改，避免重复新增。

## 1. 原子命令、变更回执与撤销

Core 定义可编码日程提案、白名单操作和变更回执。模型只能提交结构化操作，不执行代码或任意文件写入。日期、对象身份、父子关系、执行状态由 Core 验证。

一轮操作先在隔离候选状态完整验证，再通过单次原子保存提交。任一操作失败则整轮不写。请求 ID 幂等：重试和重启不会重复应用。

回执和任务状态同次保存，包含实际受影响实体、修改前后值和来源。撤销比较受影响实体的当前值，允许保留无关的后续修改；关联对象有后续编辑或执行证据时停止覆盖并解释原因。撤销也是新变更，不能删除其他设备或后续运行产生的事实。

## 2. AI 整理与助手接线

2026-09-07 用户指定文字服务改用 GLM-5.3-Flash Coding Plan，参照 earendil-works/pi 的接入方式：国内端点为 `https://open.bigmodel.cn/api/coding/paas/v4`，国际端点为 `https://api.z.ai/api/coding/paas/v4`，使用 Bearer API key 和 OpenAI Chat Completions。低延迟文字交互采用 pi 未指定思考强度时的 `thinking: {type: "disabled"}`；语音配置保持独立。先通过现有真模型日程与冲突测试再更新云端服务配置。

沿用现有聊天服务与模型配置。新增日程操作工具，携带当前日期、时区、对话及必要任务/排期上下文。保留用户明确的时间、数量、否定和纠正；只在影响执行的缺失项上追问。提案必须引用提供的对象 ID 或本轮新建别名。

模型接口优先使用当地 24 小时制 `startTime: "HH:mm"`；客户端严格解析为 Core 的 `startMinute`，避免模型自行换算分钟数出错。兼容旧 `startMinute` 输出，但同一操作不能同时提供两种表达。同名任务没有明确区分或批量指令时必须追问，不能默认修改全部。

写入完成后显示真实回执；模型未成功、校验失败、保存失败不能声称已执行。严格模式的待确认提案可取消或重新生成。当前轮取消、会话切换、重启要防止迟到结果自动写入。

等待期间持续显示当前进度，例如“正在理解你的意思…”或“正在整理日程…”，已有 Trace 不应隐藏等待提示。用户可取消；完成、失败、取消后移除等待提示。步骤耗时包含失败和取消前的实际等待，用于定位路由或日程整理的延迟，不用固定 0 代替。

## 3. 使用 Trace

现有 AI 调用 trace 保留。新增本机体验事件：输入方式、录音阶段与耗时、转写后的手动修正、日程提案/应用/确认/撤销、手动微调、同步结果与冲突处理。用操作/会话 ID 串联，不写入 API Key，不默认保存音频。

提供可查看的概览与用户主动导出；记录可关闭，保留数量/时间有上限。详细文字差异仅按明确的本机记录规则保留，默认事件以对象 ID、动作、时长和错误类别为主，导出前可检查。

## 4. Markdown 执行文件协议

当前同步主线是 App 本地日程与 GitHub 私有仓库中的 Markdown 往返，不依赖手机外部文件授权或 iCloud。系统“文件”App 中的 Markdown 绑定是可选入口；只有选择该入口时，才验证对应文件提供者、iCloud（如使用）和持久访问授权，不能把它当作 GitHub 同步的前置条件。

用户指定一个 Markdown 文件作为日程执行文件。文档有协议版本和文档 ID，任务、排期及执行记录保留稳定 ID；标题、勾选状态、日期时间、备注可直接人工编辑。未知正文应保留，格式错误不覆盖本地正常数据。

支持导入、导出、绑定本地文件、重新读取与原子写回；进出往返保持任务身份、父子关系、排期和真实执行证据。新任务无 ID 可补 ID，重复 ID 拒绝。缺失行与明确归档/删除区分，避免截断文件造成批量误删。导入和恢复也产生可审计变更。

提供基于共同基线的三方语义合并：不同对象/不同字段自动合并；同一字段并发改动形成冲突；执行证据按 ID 追加并防止篡改。保存本地、基线、远端版本，可回退；不能仅用最后写入覆盖整份文件。

## 5. GitHub 与远端 AI

iOS 通过 GitHub API 同步指定仓库、分支与执行文件，凭据安全存储。读取远端版本和 SHA，写入使用乐观并发控制；离线本地继续工作，再同步时先拉取合并，重试不会重复新增。明确展示最近同步、待上传及冲突。

远端运行器拉取执行文件，识别待处理请求，调用用户配置的 AI，使用相同协议/校验规则产生结果并写回。请求有稳定 ID，已处理不重复，AI 自身提交不造成无限触发。提供 GitHub Actions 托管入口和可在独立主机运行的入口；真实部署位置由用户选择。

本地冲突处理先确定性合并，剩余冲突调用本机侧已配置 AI 提供结构化解决结果。验证候选引用的是原始冲突及当前版本，不允许丢弃执行证据；可确定的结果可自动应用并显示回执/撤销。真正无法判断的时间或含义冲突保留双方候选并只询问具体冲突。

远端验证先用合成日程；不把个人真实日程上传到代码仓库。云端密钥不进入 Markdown、Git 历史、安装包或日志。
