# 可自定义底部导航与「更多插件」设计

状态：已确认产品方向，待实现。

## 1. 目标

Tough Trial 不再假设所有功能都必须挤进固定的五个底部 Tab。现有 `助手 / 今天 / 任务 / 随手记 / 回想` 继续作为核心模块；「我的资料与快速分享」作为独立模块存在，后续财务、联系人或扩展插件也可以拥有自己的页面入口。

底部导航只承担“我最常用的几个入口”，模块是否安装、是否启用、数据是否保留由现有插件运行时负责。用户从底栏移除一个模块，不会停用模块，也不会删除数据。

## 2. 底部 Tab 规则

- 底栏同时显示 **2–5 个 Tab**。
- 其中 **1 个永远是「更多插件」**，不可移除。
- 其余 **1–4 个位置**由用户从当前可用模块中选择。
- 用户可以拖拽 Tab 调整左右顺序，包括把「更多插件」拖到任意位置。
- 达到 5 个后，再添加模块时先提示“底栏已满”，直接进入编辑底栏；不自动替用户踢掉已有入口。
- 底栏最少保留一个普通模块 +「更多插件」，避免只剩管理入口。

首次升级沿用用户当前可见核心页面的相对顺序，并压缩为最多 4 个普通入口 +「更多插件」。新安装或新开发的模块默认出现在「更多插件」，不自动抢占底栏位置。

## 3. 「更多插件」页面

「更多插件」不是一个业务模块，而是稳定的导航与模块入口。页面优先解决两个动作：打开没有放到底栏的功能，以及编辑底栏。

页面结构：

1. 顶部：`编辑底部导航`。
2. `已启用`：显示所有已启用、但当前不在底栏的原生模块和扩展模块；点卡片直接打开。
3. `已放到底栏`：轻量展示当前 1–4 个普通 Tab，可直接进入编辑。
4. `功能与插件设置`：进入现有插件管理页，负责启用/停用、安装、权限等低频管理。

因此用户平时不需要理解“页面显示”“功能开关”两套设置；高频行为只围绕“放到底栏 / 从底栏移除”。

## 4. 编辑底部导航

采用一个独立编辑页，保持系统化和低摩擦：

- 上半区是“底栏中的项目”，使用可拖拽列表排序。
- 普通模块行提供移除操作；「更多插件」显示固定标记，只允许排序，不允许删除。
- 下半区是“可添加”，列出已启用但未放入底栏的模块。
- 点击 `+` 即加入底栏；达到 5 个时 `+` 变为不可用，并解释“最多显示 5 个”。
- 所有调整即时保存，不额外要求“完成”确认；返回即可生效。

底栏本身也支持长按后拖拽左右顺序。为了避免误触，普通点按始终只切换页面，拖拽需要长按进入重排手势。

## 5. 三层状态模型

导航状态必须与模块生命周期分开：

1. **模块启用状态**：现有 `V2ModulePreferences.disabled`，决定功能能否运行。
2. **模块页面可用状态**：现有 runtime / surface availability，决定当前是否能打开。
3. **导航布局状态**：新增独立 `V2NavigationPreferences`，只记录底栏入口和顺序。

建议数据结构：

```swift
struct V2NavigationPreferences: Codable, Equatable, Sendable {
    var schemaVersion: Int
    var orderedTabIDs: [String]
}
```

其中 `orderedTabIDs` 保存稳定的 surface ID，例如 `assistant`、`today`、`tasks`、`capture`、`recall`、`ownProfile` 和保留 ID `morePlugins`。

约束统一在导航层归一化：去重、过滤当前不可用项、总数限制为 2–5，并确保 `morePlugins` 恰好出现一次。不要把底栏顺序写进 `hiddenSurfaces`，也不要通过禁用模块实现“从底栏移除”。

## 6. 模块接入约定

每个可以独立打开的模块提供一个导航描述：稳定 ID、标题、SF Symbol、打开目标、当前可用性。业务模块不需要知道自己是否位于底栏。

「我的资料与快速分享」使用独立 ID `ownProfile`，标题建议为 `我的资料`，进入后直接显示当前身份、`我的二维码`、`分享信息`与社交二维码；联系人与扫名片仍放在该模块的“其他工具”中。

后续模块只要注册导航描述，就自动进入「更多插件」的可打开列表；是否进入底栏由用户决定。

## 7. 状态变化与回退

- 当前 Tab 被用户从底栏移除时：继续停留到编辑动作结束，随后切到排序后最靠前的可用普通 Tab；若不存在则进入「更多插件」。
- 当前模块被停用或依赖失效时：立即从可打开集合移除，并使用同一回退规则。
- 模块重新启用时：重新出现在「更多插件」，不自动恢复到底栏，避免打乱用户布局。
- 更新后发现未知或已删除的 ID：保留原始偏好备份，运行时忽略未知项并归一化可用布局。

## 8. iPhone 与 Mac

iPhone 使用原生底部 Tab Bar。Mac 端复用同一“常用模块 + 更多插件”排序数据，但可以映射为侧边栏顶部的固定入口，不要求把 iPhone 的底栏视觉照搬到 Mac。

导航布局属于轻量个人偏好。当前先本地保存；进入统一跨端同步后可以独立同步布局偏好，冲突采用最近明确编辑的布局版本，不影响任何业务数据。

## 9. 验收标准

- 可配置为 2、3、4、5 个 Tab，且每种情况下「更多插件」始终存在且仅出现一次。
- 可以添加 / 移除普通模块，并通过拖拽改变左右顺序；重启后保持。
- 从底栏移除模块后，模块仍能从「更多插件」打开，数据和能力不受影响。
- 停用模块后无法从底栏或「更多插件」打开；重新启用后出现在「更多插件」，不会擅自回到底栏。
- 当前页面被移除或停用时有稳定回退，不出现空白页、失效选中态或崩溃。
- 「我的资料」作为独立模块可被加入底栏，不占用或合并现有五个核心模块。
- VoiceOver 能读出 Tab 名称、当前选中、是否可拖动；大字体下编辑页仍可完成增删和排序。

## 10. 实施顺序

1. 建立 `V2NavigationPreferences` 与迁移/归一化规则。
2. 把 `V2RootView` 从固定五页改为按顺序渲染导航描述，并增加固定的「更多插件」。
3. 建立「更多插件」启动页与“编辑底部导航”页。
4. 将「我的资料」注册为第一个新增独立模块。
5. 做 2/5 Tab、排序持久化、移除当前页、停用模块和重启恢复的真实交互验收。
