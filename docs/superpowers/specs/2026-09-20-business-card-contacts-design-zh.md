# 我的资料、快速分享与联系人辅助工具

状态：功能设计，待实现。

## 1. 产品定位

这一模块的第一价值是**保存、展示并快速分享用户自己的公开资料**。联系人与名片扫描仍保留，但降为低频辅助能力，不再主导一级入口。

用户最高频的两个动作是：

1. `我的二维码`：面对面时打开即可让对方扫描。
2. `分享信息`：把当前公开字段通过系统分享面板发到微信 / 信息等应用，或直接复制。

首页首先显示当前身份卡片、两个主操作和常用社交账号。日常分享不要求先进入编辑态，也不要求先选择分类、标签或联系人库。

## 2. 高频信息架构

一级页面是 `我的资料`，而不是联系人库。结构按使用频率排列：

- 当前身份卡：姓名、公司 / 职位及少量已公开联系方式。
- `我的二维码`：直接进入大二维码页面，可分享二维码图片或保存到相册。
- `分享信息`：先展示将要发送的文本，再一键分享、复制或生成名片图片。
- `我的社交账号`：统一展示抖音、小红书、GitHub、X 等二维码或链接。
- `编辑我的资料`：低频维护入口，包含公开字段、社交账号和分享范围预设。
- `其他工具`：联系人库与扫名片放在这里，需要时再进入。

分享范围是辅助设置，不是每次分享的前置步骤。未选择字段、内部备注、标签、来源图片和联系记录不得外发。

### 2.1 联系人与扫名片（低频辅助）

保留以下入口，但不占一级页面：

- `其他工具 → 扫名片`
- `其他工具 → 联系人`
- Mac 端拖入 / 选择名片图片

名片流程仍为：`拍照/选图 → 自动裁切与识别 → 联系人草稿 → 用户确认 → 联系人库`。OCR/AI 识别结果只能进入草稿，不能直接覆盖已有联系人。识别失败时允许手动建立联系人且不丢原图。

## 3. 联系人草稿

草稿页面延续应用的连续文档式输入原则。第一行优先显示姓名，下面自然排列识别结果；只有需要修改时才点入字段。

首期识别字段：

- 姓名
- 公司 / 组织
- 职位 / 部门
- 手机 / 电话
- 邮箱
- 微信 / 其他即时通讯账号
- 网址
- 地址
- 名片备注 / 其他原文
- 名片原图

字段均允许为空。系统根据版面和文本推断字段；低置信度内容标出来源片段，用户确认后才成为正式数据。

保存时提供一个主要操作「保存联系人」。不额外要求填写标签、关系类型、提醒时间等信息。

## 4. 联系人库

联系人库先提供三种最常用视角：

- `人物`：按姓名浏览和搜索。
- `公司`：自动按公司聚合，不要求扫描时先选公司。
- `最近`：按创建、编辑或人工记录的最近联系时间排序。

联系人详情显示：基础资料、来源名片、标签、备注、关联记录，以及后续可选的联系记录。

搜索同时覆盖姓名、公司、职位、电话、邮箱、标签和备注。

### 4.1 我的资料与快速分享

「我的资料」是本模块一级入口。它复用联系人字段语义与名片视觉组件，但属于用户自己的资料，不参与重复联系人检测，也不会混入普通联系人搜索结果。

首次进入只要求填写希望公开的内容；姓名之外全部可选。支持保存多张身份名片，例如「工作」「个人」「活动」，默认只展示一张当前名片，避免增加日常操作负担。

我的名片支持三种直接分享方式：

- `分享信息`：把用户勾选的姓名、公司、职位、电话、邮箱、微信、网址等生成简洁文本，通过系统分享面板发送到微信等应用。
- `分享名片图片`：按 Tough Trial 主题生成一张可保存、复制或发送的名片图片；用户也可以把自己的实体名片照片设为分享图片。
- `二维码`：根据当前分享字段即时生成二维码。首期使用标准 vCard 内容，扫码者无需安装 Tough Trial 即可读取联系人信息；同时提供「保存二维码图片」。不同扫码应用对 vCard 的处理可能不同，因此二维码页同时保留可复制的文字信息作为兜底。

分享页不要求进入编辑态。默认显示当前名片预览和三个主要操作，点「分享范围」才展开字段开关。每次分享都只包含当前明确选中的字段；备注、内部标签、来源图片、联系记录等内部资料默认永不进入分享内容。

可保存轻量分享预设，例如「工作公开」「只留微信」「活动交换」，预设仅保存字段选择，不复制一份联系人数据。修改我的名片后，所有预设使用最新字段值。

### 4.2 社交媒体与二维码

「我的资料」下提供一个统一的「社交媒体」区域，用于保存和展示个人对外账号。首批内置抖音、小红书、GitHub、X，后续平台通过同一数据结构扩展。每个平台条目可以保存：账号名、主页链接、二维码图片、显示名称和是否加入当前名片。

使用原则：

- 默认列表只显示平台图标、账号名和二维码缩略图，避免把名片主页变成复杂的社交资料表单。
- 点某个平台后可展示大二维码，并提供「复制账号」「打开主页」「分享二维码图片」。
- 抖音、小红书等以二维码交换为主的平台允许只存二维码图片；GitHub、X 等链接型平台允许只存 URL/账号，不强制二维码。
- 用户可以直接从相册导入现成二维码；后续可增加扫码识别主页链接，但导入图片本身不需要联网。
- 分享名片时，社交平台作为独立字段组选择。未选中的平台和二维码图片不得外发。
- 二维码属于用户资料附件，首期本地保存；进入统一备份/同步时与联系人附件一起版本化。


如果以后提供网页端公开名片，可新增带撤销能力的短链接二维码；它属于后续云端能力，不作为首期扫码分享的依赖。

## 5. 整理能力

整理是保存后的可选动作，不阻塞录入。

### 5.1 标签

标签为多选，例如「客户」「供应商」「媒体」「朋友」「活动 2026」。标签可以由 AI 建议，但新增或修改标签不作为保存前置条件。

### 5.2 重复联系人

保存前只做轻提示：

- 相同手机号或邮箱：高置信度重复。
- 姓名 + 公司相同：中置信度重复。
- 仅姓名相同：弱提示。

重复时提供「查看已有联系人」「合并」「仍然新建」。系统不得静默合并。

合并时按字段展示差异；电话、邮箱等允许保留多个值，原始名片图片和来源记录全部保留。

### 5.3 AI 整理

AI 可以：

- 从名片版面恢复字段含义。
- 统一中英文姓名、公司和职位格式。
- 建议标签。
- 根据已有联系人提示可能重复。
- 从用户的备注中提取“在哪里认识 / 下一步要做什么”等候选信息。

所有会改变正式联系人事实的 AI 结果先形成候选，用户确认后写入。

## 6. 与任务、助手和随手记的关系

- 从联系人详情可以「创建任务」，例如“下周联系 Alice”，任务只保存联系人引用和用户填写的任务内容。
- 助手可以读取用户授权范围内的联系人，例如“上周活动认识的做芯片的人是谁”；读操作可自动进行，修改联系人仍走明确的编辑/确认流程。
- 随手记中的文字如果明显包含联系人信息，可建议“建立联系人”，但不自动创建。
- 名片原图进入现有附件库；联系人只保存不可变 Asset 引用。

## 7. 数据模型建议

新增独立 `core.contacts` 领域，避免把联系人塞进普通 Capture 文本或任务模型。

首期核心对象：

- `Contact`：稳定 ID、姓名、组织、职位、联系方式、地址、标签、备注、来源与时间。
- `ContactSource`：名片图片、Capture/导入来源、识别文本摘要和来源 revision。
- `ContactDraft`：扫描后尚未确认的候选字段。
- `ContactMergeProposal`：重复检测和逐字段合并候选。
- `ContactInteraction`：后续阶段的人工联系记录；首期可以只预留 schema，不强制提供 UI。
- `OwnCardProfile`：用户自己的名片身份，复用联系人字段语义，但有独立 ID、显示名称、默认身份与可分享字段配置。
- `ContactSharePreset`：某张我的名片的分享字段集合，例如「工作公开」或「只留微信」；不复制字段值。
- `SocialProfile`：平台、账号名、主页 URL、二维码 Asset 引用、显示名称和是否加入名片；属于 `OwnCardProfile`，不混入普通联系人字段。

联系人正式写入通过 typed command，并沿用现有 receipt / undo / trace 机制。Trace 不保存名片正文或完整电话号码等个人资料。

二维码和分享文本均在本机按需生成，不额外持久化包含全部联系方式的分享副本。名片图片如果由用户明确保存，再进入附件库。

## 8. 插件与组件边界

模块建议登记为 `core.contacts`，可选依赖：

- `core.capture`：从随手记创建联系人来源。
- `core.imports`：图片导入与识别。
- 附件能力：保存原始名片图片。
- 助手能力：AI 字段识别、标签与重复建议。

基础 UI 复用现有图片选择、附件预览、连续文档输入、候选确认组件。联系人字段编辑器作为 `Contacts` 业务组件存在，不建设通用动态表单框架。

## 9. 同步与隐私

首期联系人本地保存。当前 GitHub 日程同步不自动包含联系人。

后续接入统一备份/同步协议时，联系人、名片原图和联系记录分别版本化；冲突按字段产生候选，不使用“整条最后写入覆盖”。名片原图属于敏感个人数据，远端备份必须明确展示数据范围。

系统联系人（Apple Contacts）导入/导出属于后续独立能力。未获得用户明确授权时，不读取或写入系统通讯录。

## 10. 分阶段实现

| 阶段 | 用户可用能力 | 完成标准 |
| --- | --- | --- |
| C1 · 扫描与建立（次优先） | 拍照/选图、OCR、联系人草稿、确认保存、原图保留 | 识别失败可手填；取消不创建正式联系人；重启后正式联系人仍在 |
| C2 · 联系人库（次优先） | 人物/公司/最近、搜索、详情编辑、标签 | 搜索覆盖主要字段；编辑/撤销可靠；大字体和长公司名可用 |
| C3 · 我的资料与快速分享（首优先） | 我的资料首页、当前身份、微信等系统分享、名片图片、vCard 二维码、社交媒体账号/二维码、分享范围预设 | 打开模块即可看到自己和两个主分享入口；不进入编辑态也能分享；未勾选字段绝不外发；扫码方无需安装 Tough Trial |
| C4 · 整理 | 重复提示、逐字段合并、AI 标签与备注候选 | 不静默合并；来源全部保留；AI 只修改候选 |
| C5 · 关联 | 联系人→任务、助手只读检索、随手记建议建立联系人 | 引用稳定；删除/停用来源后历史联系人仍可读 |
| C6 · 跨端 | Mac 同功能、联系人/名片进入统一备份与同步 | 双端字段冲突可恢复；附件不丢失；范围说明准确 |

首期实现顺序调整为 **C3 → C1 → C2**。先把“展示我自己、面对面扫码、分享信息和社交二维码”做成完整高频闭环；联系人扫描与联系人库随后补齐为低频辅助工具。三者都不依赖云端 AI。二维码使用本机 Core Image 生成，OCR 可使用本机 Vision，AI 只作为后续整理增强。
