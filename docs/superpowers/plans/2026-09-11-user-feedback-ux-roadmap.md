# 用户反馈体验优化计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让用户能够直接修改和完成任务、顺畅输入长文本与语音，并找到记账和整理能力。

**Architecture:** 复用 SwiftUI 页面、App Store 和既有 Core 命令，所有入口操作同一份任务或账单。先修复基础交互，再统一输入和复验已有能力；本文件跟踪分批实现和验收状态；A/B/C 已实现并完成定向本地回归，D 已完成本地修复与生产搜索客户端复验，真实模型联网对话待验收，真机验收另行记录。

**Tech Stack:** SwiftUI、现有语音服务、ToughTrialV2Core、XCTest。

**Spec:** `docs/spec.md`；任务行为遵循 `2026-05-30-tough-trial-interaction-redesign-design-zh.md`，助手遵循 `2026-09-11-assistant-home-design.md`，记账遵循 `2026-09-09-unified-capture-and-ledger-design-zh.md`（均在 `docs/superpowers/specs/`）。下列交互方案为本次建议；实施前把涉及行为变化的具体设计更新到对应规格。

## 全局约束

- 今天保持执行导向，不展示任务分类标签，不加入 Dreaming 或分类分析；分类入口放在任务详情/编辑中。
- 普通编辑和完成动作不依赖 AI；复用同一任务 ID，不重新创建副本，不清空执行历史或累计用时。
- 账单分类始终人工确认，新的 capture/ledger/media 数据仍按既有本地存储边界处理。
- 保留工作区已有改动。每批只修改对应范围的应用代码、测试和规格，并在验收后更新 roadmap。
- 每个可见交互控件都须实际点按/输入并核对反馈和领域状态；截图或控件存在不能单独作为通过证据。

## 项目内部组件组与迁移边界

用户补充并确认：采用类似 Vue Component 的复用思路，主要服务本项目本身及参与项目的开发者。以下是本批 A/B/C 的共同实施方式；A 已实现并通过本地与两种尺寸模拟器验收，B/C 已完成实现和定向本地回归；自然听写和真机验收继续开放。

### 组织和职责

在现有 `Sources/ToughTrialV2App/` 内渐进建立以下分组；`Components/Tasks/` 已在 A 落地，其余目录随 B/C 的实际复用需求建立。首版不新增 package/target，不一次性移动所有页面。

| 分组 | 责任 | 边界 |
| --- | --- | --- |
| `Components/Input/` | 共用长文本输入、语音控制与草稿绑定 | 接收文本和明确状态/事件，不持有整个 App Store，不自行创建任务或账单；共用实现不等于全局共用一份草稿 |
| `Components/Tasks/` | 任务编辑器、字段和编辑状态 | 新增/已有任务/提案共用字段与校验表现，向业务接线层发出保存/取消事件 |
| `Components/Ledger/` | 随 C 批次整理记账编辑器 | 组合基础输入，保留金额、币种、来源及人工分类确认，不把任务与账单塞入万能表单 |
| 现有页面与 Store | 导航、入口默认值、读取对象、提交与反馈 | 页面组合组件；Store 调用已有 Core 命令，保留模块门禁、持久回执、撤销与同步规则 |

先提取已有重复交互；保存/取消、附件等只有出现真实复用需要时再单独抽取。组件组属于源码组织，不新增用户可见功能模块、开关或插件注册项。

### 同一编辑器的入口契约

组件输入使用明确的编辑模式、初始草稿和提交状态；创建/编辑目标由强类型模式表达，避免多个布尔开关组合出非法状态。A 已采用 `V2TaskEditor.Mode` 和独立本地草稿，不新增第二套持久化 Task schema。

| 入口 | 初始数据 | 保存含义 |
| --- | --- | --- |
| 任务页新增 | 空草稿，默认不排期；有当前父任务时保留父 ID | 新建任务，继承明确的父节点语义 |
| 今天新增 | 空草稿，默认当天 | 沿现有事务创建任务及当天安排 |
| 已有任务详情 | 按稳定 ID 读取当前任务，保留未编辑字段 | 更新原对象，保留身份、执行证据与未修改排期 |
| 快速待办/快捷入口 | 空草稿或入口提供的文字，默认不排期 | 调用既有正式任务创建流程 |
| 助手未确认提案 | 提案中的标题/备注/日期及候选身份 | 只更新该提案，正式写入仍由确认流程触发 |

保存事件提交当前草稿，成功才退出编辑；失败保留输入并显示原因，提交期间阻止重复提交。取消不发出领域写入，关闭时的未保存处理保持一致。每个对象/会话独立草稿；重新打开另一个任务不残留上一任务文字。日期字段使用现有任务与排期契约，编辑器不得暗中新增日期或清除其他安排。
