# 文档式任务输入验收（2026-09-12）

用户修正：标题/备注不应要求分别填写或切换；参考文档，第一段为标题、回车后直接写正文。新版编辑器应与应用风格一致。此记录接续 B 批次，旧系统 Form 截图仅为历史证据。

## 最终结论

本地实现完成：单一文档输入、应用主题、各入口复用及提案草稿稳定性已验证；19 项 App 检查、小屏 3 项文档 UI 和大屏任务/提案定向交互均有通过证据。旧硬件全选快捷键用例已改为手机原生长按“全选”；真实 IME、自然口述和真机安装仍待验收。

## 已实现

- 一份连续文档草稿，回车进入正文；正文可空。保留既有 title/note 存储、任务 ID、日期、父节点及提案确认规则。
- 原生 UITextView，首段使用应用圆角粗标题、正文使用正文样式；应用纸色背景、蓝色保存、固定顶部取消/保存与底部语音，去掉系统 Form 字段卡片。
- 无“标题/备注”输入框与听写目标切换；识别方式只在设置页选择。语音按开始时的 UTF-16 光标/选区插入，同一片段的修订不重复追加，取消恢复原文/选区。
- 中文 marked text 期间不替换全文/选区/样式；保存或开始听写前结束当前输入焦点。未改动旧草稿时保留原字段，避免将旧多行标题重新拆分。
- 详情直接展示已有正文，空正文不再显示“暂无备注”。日期只在需要的助手提案中保留。
