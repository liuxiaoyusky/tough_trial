## 检查中发现的问题

1. 两个旧回归用例按系统 TabBar 定位，当前 App 使用自定义底栏；源码和失败日志证明定位方式不符。只把相关测试改为现有 root.tab.tasks 标识，并等待真实入口出现，未修改导航业务逻辑。
2. 最大辅助字号下，列表圆圈随 title3 撑破 44 点按钮，底栏文字变成省略号。已分开固定符号大小 / 点击区，并限定紧凑标签展示档；后续原生图核对修复效果。
3. 合批中的列表用例在「今天」准备阶段点选后没有找到目标开始按钮，辅助树显示实际选中另一条任务。该失败并未发生在新列表内；测试改为先把整个目标滚动到固定底栏 / 悬浮按钮上方，再点按和断言目标动作出现。没有改今天的选择或计时实现，不把它写成产品逻辑已修复。

4. 首次 `test-without-building` 深色复验没有进入预期空态，录像中仍有此前合成任务，空态前置断言失败；该次来源不作为最终验收。录像也明确复现纸白背景上的白色系统栏。任务页显式采用浅色后，以指定构建号正常编译再验；没有改数据加载来掩盖前置失败。

失败结果 `/private/tmp/tough-trial-20261005-design-foundation-regression.xcresult` 、`...-final-light.xcresult` 与 `...-dark.xcresult` 原样保留，不把整批失败标成通过。
