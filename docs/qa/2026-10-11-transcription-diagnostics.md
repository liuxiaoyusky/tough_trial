# 2026-10-11 · 转录失败定位与工作台证据

本轮补上“看不出失败或卡住在哪一步”的诊断缺口。iPhone 录屏和下载视频的原始失败素材仍未取得，不能由本轮合成素材结果确认手机根因。

## 已确认的缺口与修改

旧代码只在 OSLog 写入系统错误 domain/code，转录记录只保存一句提示。处理中重开又覆盖为通用中断提示；音频转换器也会用通用 conversion 错误替换系统原错误。进度文字不能可靠地区分音频读取、转换和识别。

现在记录保存类型化阶段；读取、提取、转换及文字落盘的错误带实际操作上下文，保留系统原错误。失败记录含版本、系统版本、当前尝试的方式、媒体类型、阶段和至多五层错误码。切换方式失败不改变旧稿的 provider；重试清除旧诊断，保留文字和断点。旧 JSON 未包含新字段仍可读取。

诊断不复制标题、文件名或路径、媒体、逐字稿、摘要、密钥、系统描述或服务返回原文。只使用限定格式的错误 domain 和数字 code；诊断留在本机，用户自行复制。诊断保存本身失败时，页面说明尚未保存，并保留可复制的信息。此存储失败提示的真实磁盘故障交互尚未验收。

重开处理中记录时，显示“最后记录阶段”，明确没有系统错误回执，不能推断是用户暂停、系统终止、权限或模型问题。并行的音频读取与识别仍属于一个处理流水线；只有捕获到的操作错误可以确定失败操作，最后阶段不等于根因。

## 本轮失败如何追踪

- `exec_9dd626a80f0cce6c801efa52` 编译失败：包装闭包提前捕获未初始化 self，音频 buffer 的隔离检查失败。使用局部输入格式与同一 actor 内的直接读取错误上下文后通过。
- `exec_e2b2c9ece08d7766be765b24` 超时：真实模型测试尚未完成导入。调用栈采样 `exec_65bab298131ac4732d7d5fad` 定位到 `importMedia → copyItem → clonefileat`，不是模型识别。`exec_1d3d4b261c02348173b479e2` 的字节复制和命令行克隆均成功；用临时目录中相同摘要的素材后，Mac 与模拟器的视频测试通过。XCTest 的环境差异尚未确定具体机制，不改产品复制逻辑，也不把它当作手机根因。
- `exec_31fc78cc25ced1134359c66c` 同时保留视频导入超时与 UI 失败。附件导出 `exec_7c4065e5ffda7c2f6af5db4c` 显示父级 DisclosureGroup 的标识覆盖了文本和复制按钮；移除父级标识后真实点击通过。
- `exec_891f0f81832ddfc49917cc22` 与 `exec_c3b6b19680bb9993a61d2a30` 进程成功，但运行期间有已知 App 修改，来源回查失效；不作为当前通过门禁。最终检查使用上表的完整终态和当前来源。

工作台把失败与修正后的检查分别保存，不能通过重算旧来源摘要抹掉失败。进程通过、产品效果和用户验收仍分别判断。
