# 随手记与理账：首个本地闭环

日期：2026-09-09。范围：本地实现与模拟器验收。此文不把 fixture 提取结果当成真实 GLM/ASR 识别质量验收。

## 现在能用

- 新增「随手记」底部入口，页内「记录 / 理账 / 收纳 / 灵感」。保留今天、任务、助手、回想。
- 混合文字或听写 → 点整理 → 标准候选 → Core 校验 → 账单、原有任务/回想、灵感、以后想做、Others。
- 默认逐项立即保存并展示状态/撤销；原有严格确认设置也适用。账单分类始终需要人工确认，完整但未确认分类的账单正式留在 Others；缺金额/币种的候选不计入总额。
- 账单支持金额+描述手动输入、明确币种与收支方向；与 AI 输入使用相同 LedgerEntry、领域命令及列表。不同币种独立统计，转账不混入支出。
- 手动确认初分类/改类，新建独立分类/子类，合并前显示受影响记录数与按收支/币种拆分的金额，包括零记录分类；分类调整可撤销，后续修改时拦截。
- 修改原文会保留旧 revision；重新整理显示旧结果和新候选，必须确认替换。替换通过 staged snapshot 校验和提交，任一已有任务/回想被后续修改时整组停止。
- 回想在现有 V2RecallEntry 上追加，保留原文、引用和手写标记。未保存的回想草稿会拦截追加；干净缓存会更新，不掩盖新正文。
- 图片与 PKDrawing 笔画原件先存入文件，再保存引用；图片/手写用本机 Vision OCR 派生文字，无法识别时原件仍可回看。手写可以重新打开继续编辑。
- Apple 听写保留文字。FunASR 点完成后先保存 WAV，再上传整段转写；转写失败可以重试，原音保存回调成功后不重复保存。已有助手没有启用持久化回调，原行为保持。
- 元数据 Trace 复用原有开关、30天/2000条限制，包含来源版本、批次、候选、回执、模型和处理阶段；原文/图片/音频不进入使用日志。业务来源与回执不因关闭 Trace 消失。

## 分层与存储

UI 只通过 V2CaptureStore 的命令和类型化状态交互；AI client 无写入接口。V2CaptureContract 的字段定义同时驱动提案解析与模型提示。领域数据保存于原 V2AppSnapshot 的可选 capture 扩展，旧快照缺少此字段时默认空；不支持的 capture 结构版本拒绝加载。资产独立文件使用 UUID、SHA-256 和长度校验。

候选证据提供 blockID+原文 quote；Core 核对后解析并保存 Unicode scalar 区间、源 revision 和资产 ID。不会信任模型填写持久化 ID、保存路径或成功状态。

任务由既有 applyScheduleProposal 生成；捕获回执和任务回执同一次 snapshot 提交。撤销也调用原有任务领域逻辑。没有另一套“AI 任务”数据或执行卡片。

## 明确未覆盖 / 下一阶段

- 尚未在本轮用真实 GLM / 百炼账号测混合提取质量、计费或端到端速度；生产 client 使用应用当前文字模型配置，未改成另一服务。
- 当前实现单条来源重新整理、分类手动细分/合并及改类；全库 AI 批量分类建议、逐笔差异筛选、疑似同一消费跨来源重复提示尚未实现。
- attributes/FieldDefinition 的可注册扩展字段和未来未知扩展原样保全仍是后续设计；本版仅开放明确领域字段和动态分类，未知候选字段会拒绝。
- 图片/手写使用本机 OCR，不含视觉模型语义理解；Apple 原始音频归档尚未实现，保留其原有文字听写流程。
- capture/ledger/category/media 的版本化 Markdown 同步协议尚未实现；现有 schedule.md 仍只同步原有任务数据。
- 大量历史来源/媒体的空间回收、按条件检索、跨来源去重和更细字段级修正指标待后续优化。
