# 后端 MVP 引擎需求细化

状态：已确认，作为本地引擎实施输入
日期：2026-07-01
来源：产品需求部阶段输出

## 1. MVP 后端范围

MVP 后端先做一个可用的本地任务执行引擎，覆盖四件事：

- `任务核心模型`：目标、任务、子任务、维护 / 孤立任务、父子结构、完成状态、进度信号。
- `今天执行记录`：开始、暂停、结束、完成、恢复完成、多任务并行计时、Zen 写回任务。
- `计划草稿与计划项`：聊天 AI 生成结构化草稿，用户确认后写入计划；未确认前只保存为草稿。
- `回想证据基础`：按日期读取真实执行记录，允许回想条目引用任务、时间段、临时插入、计划偏差。

MVP 后端目标不是做完整项目管理系统，而是让产品先能真实记录：

- 我有什么任务。
- 今天做了什么。
- 计划过什么。
- 回想引用什么。

## 2. 必须支持的实体

### TaskNode

任务 / 目标 / 阶段 / 子任务统一实体。

必须支持：

- `parentID`
- `children`
- `contextID`
- `goal / commitment / maintenance` 内部类型
- `notStarted / active / paused / done / archived` 内部状态
- 叶子节点完成信号：完成为 `1`，未完成为 `0`
- 父节点完成信号：按子节点计算，具体算法在设计阶段冻结

注意：任务类型不展示在 `今天` 执行界面。

### TaskContext

一个任务结构上下文，例如长期目标、项目、维护组。

用途：

- 任务页结构图切换。
- 任务归属。
- 不做复杂 workspace。

### PlanDraft

AI 计划草稿。

必须支持：

- 保存
- 继续修改
- 接受
- 废弃

未接受前不能写入正式任务或计划项。

### PlanItem

某天或某段时间的计划意图。

必须支持：

- 引用已有任务。
- 代表临时承诺。
- 允许只有日期，没有具体时间。

计划项不是执行事实。

### ExecutionSegment

真实发生的时间段。

必须支持：

- `taskID?`
- `startAt`
- `endAt?`
- `source`

`source` 至少支持：

- 普通计时
- Zen
- 临时插入

允许多个未结束 segment 并行存在。

### RecallEntry

某天的反思文本。

必须支持：

- 引用多个 `ExecutionSegment`
- 引用 `TaskNode`
- 引用 `PlanItem`
- AI 整理草稿不自动保存

### DreamingSuggestion

模型主动建议。

必须支持：

- 只作为草案存在。
- 用户确认后才转成任务、计划项或拆解节点。

## 3. 必须支持的业务动作

### 任务动作

- 新建任务、目标、子任务、维护任务。
- 修改标题、父节点、上下文、状态。
- 完成任务。
- 恢复未完成。
- 归档任务。
- 读取任务树。
- 计算节点完成信号。

### 今天执行动作

- 把任务加入今天。
- 紧急插入今日任务。
- 开始任务计时。
- 暂停 / 恢复当前时间段。
- 结束当前时间段。
- 标记任务完成。
- 恢复已完成任务。
- Zen 结束后写入同一个 `ExecutionSegment` 模型。
- 按日期读取今天真实执行记录。

### 计划动作

- 保存 AI 计划草稿。
- 草稿接受后生成 `PlanItem` 和必要的新任务 / 子任务。
- 草稿局部编辑后再接受。
- 支持“只拆解”模式。
- 支持“只排期”模式。
- 用户未确认时不写 durable task / plan。

### 回想动作

- 按日期读取执行证据。
- 创建 / 更新当天回想文本。
- 插入证据引用。
- 计算用于回想的时间比例和偏差分析。
- AI 整理草稿后等待用户保存。

时间比例和偏差分析不进入 `今天` 页。

### 持久化动作

- 本地保存所有核心实体。
- App 重启后恢复任务、计划、执行记录、回想。
- active segment 如果 App 被杀掉，重新打开后仍能判断它是未结束时间段。
- 支持基础数据版本号，后续可迁移。

## 4. 第一阶段不做什么

- 不做前端视觉打磨。
- 不做完整云同步、多设备协作、账号系统。
- 不做复杂权限、团队项目管理、看板、甘特图。
- 不做自动冲突解决、容量计算、任务替换建议。
- 不让 AI 未经确认写入任务、计划、memory。
- 不在 `今天` 页展示长期目标分类、时间比例、Dreaming 推荐。
- 不把 `计划` 页做成日历页或任务详情页。
- 不把 `回想` 页做成默认分析 dashboard。
- 不追求复杂 recurrence engine；周期任务先支持“拆成多个计划项”的 MVP 能力。

## 5. 验收用例清单

### 任务树

- 新建一个目标，添加三层子任务，读取时父子关系稳定。
- 完成一个叶子节点后，该节点完成信号为 `1`。
- 未完成叶子节点完成信号为 `0`。
- 父节点完成信号按子节点计算，结果可测试。
- 维护 / 孤立任务可以存在，不强行挂到长期目标。

### 今天执行

- 今日任务可以开始计时，生成未结束 `ExecutionSegment`。
- 暂停 / 结束后写入 `endAt`，任务累计用时正确。
- 两个任务可以并行计时。
- 已完成任务可以恢复未完成。
- Zen 结束后，如果有关联任务，用时写回同一任务模型。
- 未关联 Zen 也能保存为执行记录。

### 计划

- AI 草稿保存后不会改变正式任务和计划。
- 用户接受草稿后，才生成计划项或子任务。
- “只拆解”只生成任务结构，不安排时间。
- “只排期”只生成计划项，不改任务结构。
- 周期目标可以拆成多个计划点。

### 回想

- 能按日期读取真实执行记录。
- 回想文本可以保存并再次读取。
- 回想可以引用某个执行时间段。
- 计划了没做、没计划但做了，可以作为偏差事件被计算或列出。
- 时间比例分析只供回想 / 分析使用，不污染今天执行流。

### 持久化

- App 重启后任务树仍存在。
- App 重启后历史执行记录仍存在。
- App 重启后未确认计划草稿仍是草稿。
- App 重启后回想文本和引用仍存在。

## 6. 推荐默认决策

为降低 MVP 复杂度，产品需求部建议先采用以下默认：

- 本地持久化：先用 JSON 文件仓库，不上 SwiftData。
- `TaskNode` 类型：允许为空，快速新增任务不强制分类。
- 父节点完成信号：递归叶子平均。
- `PlanItem` 时间：允许只有日期，没有具体时间。
- 未关联 Zen / 执行记录：保留为未归属时间段，供回想引用。
- 周期任务 MVP：只生成多个计划项，暂不做自动重复规则。
