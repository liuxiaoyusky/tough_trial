# Tough Trial 交付路线

更新日期：2026-07-23

## 当前阶段

当前目标是完成 **M1：本地闭环原型**。四个页面的大局职责已经确定，接下来
按“设计确认 -> 实现 -> 自动检查 -> 模拟器截图/人工验收”的顺序逐阶段交付。

## 执行原则

- 每个阶段先给出可判断的设计或需求结果，再进入实现。
- 自动检查通过不等于视觉验收通过，两者分别记录。
- AI 只能生成草稿；写入任务、计划或其他持久数据必须由用户确认。
- 优先完成真实闭环，不为未来能力提前增加界面负担。
- 每个阶段只提交自身文件，不混入工作区已有的无关改动。

## Phase 0：计划页检查点

目标：把已经确认的 A 版计划页固化为可追踪基线。

- 空白、AI 追问、草稿待确认三个状态。
- 聊天式低门槛输入，不强制用户先填写结构化表单。
- 草稿可保存；确认后通过 `V2PlanEngine` 原子写入正式计划。
- 核心检查、iOS 构建、紧凑尺寸截图与产品规格同步。
- 创建只包含本阶段文件的 scoped commit。

## Phase 1：回想页设计与接线

目标：把已有证据能力变成安静、可日常使用的反思页面。

- 先用 Creative Production 形成一版可判断的主界面设计。
- 默认只呈现写作面和一句 placeholder，不铺开摘要、比例或证据详情。
- 证据引用采用轻量入口；需要时再展开选择和定位。
- 接入 `V2RecallEngine` 的日反思、执行证据和保守偏差查询。
- 以空白、写作中、引用证据三个状态完成模拟器验收。

状态：已完成。证据窗默认关闭，按需覆盖在编辑器右上方；文字和引用关系按天
持久化，未保存草稿在日期切换时保留。

## Phase 2：端到端本地闭环

目标：用一个真实场景验证四个页面不是四个孤立原型。

验收场景采用“这周我想跑 10 公里”：

1. 用户在 `计划` 中自然表达意图。
2. 系统追问必要信息并生成结构化草稿。
3. 用户确认后，安排出现在相应日期和 `任务 / 时间`。
4. 当日任务进入 `今天`，产生真实开始、暂停、结束与用时记录。
5. `回想` 能引用这些执行证据完成当天反思。

该阶段结束时，M1 完成。

状态：自动闭环检查已通过。跨页面人工操作和真机验证保留到 Phase 7 的独立
QA，不把自动检查提前表述为最终体验验收。

## Phase 3：真实 AI 计划能力

目标：把确定性原型规划器替换为可测试、可降级的模型客户端。

- 固定输入、输出与系统场景，输出继续经过本地域模型校验。
- 并行判断是否需要拆解、规划时间、关联目标或作为孤立任务。
- 模型失败时保留用户输入和草稿，不产生静默写入。
- 真实模型与本地确定性测试替身分离，保证核心检查可重复。

状态：代码与契约已完成。App 通过 `V2PlanningClient` 调用规划器，Responses API
请求使用严格 JSON Schema 且关闭服务端存储；模型返回的日期、时间、任务引用会
先在 Core 中验证。未配置开发环境变量时明确使用“本地基础规划”，远程错误直接
呈现，不静默替换结果。真实供应商联调仍需要外部 API 凭据，不纳入本地通过结论。

开发联调配置：

- `TOUGH_TRIAL_AI_API_KEY`
- `TOUGH_TRIAL_AI_MODEL`，未指定时使用 `gpt-5-mini`
- `TOUGH_TRIAL_AI_ENDPOINT`，未指定时使用 OpenAI Responses API

## Phase 4：用户记忆与上下文

目标：让计划建议逐步理解用户，而不是要求用户反复填写约束。

- 只保存可解释、可查看、可更正的习惯与偏好。
- 区分明确事实、模型推断和临时上下文。
- 记忆只影响建议，不绕过用户确认。

状态：已完成本地记忆闭环。记忆独立保存在 `v2-memory.json`，计划请求只读取
当前有效版本；用户可从计划页菜单查看、新增、纠正或彻底忘记。纠正会保留版本
来源，忘记会物理删除整条版本链，7 天临时上下文到期后不再进入规划请求。当前
没有自动提取或自动写入记忆，模型推断仍需后续由用户明确确认。

该阶段结束时，M2：可日常使用的 MVP 完成。

## Phase 5：Dreaming

目标：在已有真实使用证据后提供主动但克制的建议。

- 至少积累 7 天真实执行与计划数据后再启动。
- 只包含两类建议：空闲时间安排、长期目标继续拆解。
- Dreaming 不进入 `今天`，也不自动写入持久数据。

状态：已完成受门槛保护的本地候选层。滚动 28 天内必须同时满足：至少 7 个
有证据的不同日期、至少 3 个执行日、至少 3 个计划日、首尾跨度至少 6 天。
空闲排期只读取用户明确保存的星期与时间窗口，日历空白不会被推断为空闲；
目标拆解只针对未完成且没有子节点的长期目标。候选仅在 `计划` 空白页出现，
点开后仍是普通待确认草稿，不写入 `今天` 或持久快照。

## Phase 6：iOS 原生能力

- 通知、Live Activity、语音输入与必要的系统快捷入口。
- Apple Pencil / 类 GoodNotes 手写作为 `回想` 的后续目标。
- 每项能力独立验证价值，避免一次性扩大 MVP。

## Phase 7：独立 QA 与 Beta

- 核心行为回归、JSON 持久化恢复和异常路径检查。
- 主要 iPhone 尺寸的视觉回归与可访问性检查。
- 真机连续使用、性能和数据安全检查。
- TestFlight 交付与问题分级。

该阶段结束时，M3：V1 Beta 完成。
