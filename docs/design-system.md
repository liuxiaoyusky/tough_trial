# Tough Trial V2 视觉设计系统

状态：采用方案 2「微暖纸白」作为第一版视觉基线
更新日期：2026-10-05

## 设计原则

- 颜色表达职责，不表达页面。四个主页面共享同一套语义角色。
- 中性色保持轻微暖意，但不做成手账、羊皮纸或单一米色主题。
- 蓝色只表达主要操作与当前选择；任务状态与目标分支使用独立色组。
- 执行状态不依赖文字标签之外的单一颜色，图标、文案和状态必须共同成立。
- 页面代码优先引用语义角色，避免直接写 RGB、Hex 或按页面命名的颜色。

## 页面应用规则

- `今天`：画布、中性表面、主要操作色和任务状态色；不出现目标分支色。
- `任务 / 结构`：结构图直接使用页面画布，不包进额外可见卡片；目标分支色只辅助识别关系，不表示执行状态。10/5 完成节点改为中性文字、删除线、勾选与「已完成」文字，不靠绿色填充判断是否完成。
- `任务 / 结构`：直接显示倒树，移除目录切换；总览只有一个「未分类」展示根，连接所有无父任务的顶层节点。首屏定位展示根，宽树和深树通过横向拖动、聚焦、收起/展开和缩放进入，不把整棵树压缩到首屏；聚焦真实分支时隐藏展示根。
- `任务 / 时间`：只表达时间位置与完成状态，不按长期目标重新分组或着色。
- `任务 / 时间`：年、月、周、三日、日共用连续日历画布；周视图允许任务并排重叠，三日和日提供更高可读性。
- `任务 / 鱼骨`：目标分支色用于筛选与区分同一完成时间轴上的目标来源。
- `计划`：主要操作色负责对话动作，草稿和确认状态使用中性表面层级。
- `回想`：事实记录以中性色为主，只在证据定位和分析引用时使用强调色。

## 2026-10-05 · 任务列表阅读层级

本轮采用 `design-foundation` 的灰度层级、亲疏分组、减少重复边框和多通道状态原则。继续以本文件为设计规则源，沿用微暖纸白、系统字体和原生 SwiftUI；不新建另一份 DESIGN.md，也不把网页重绘当原生外观。

任务列表的核心任务是找到要继续做的事、打开编辑，以及完成或恢复任务。以下规则仅在本轮列表落地，其他页面按后续评审逐页迁移。

| 规则 | 生产组件 / 参数 | 检查方式 |
| --- | --- | --- |
| 三个子列表通过间距建立分组，组标题先于内容，数量弱于标题 | `V2TaskListView`；组间 24 点、组标题与内容 8 点；数量使用 `bodySmall` / `textSecondary` | 灰度看分组，核对原生辅助标签中的组名与数量 |
| 同组任务共享轻量表面，用短分隔线替代每行圆角卡片与外框 | 进行中 / 未开始共享 `surfaceRaised`，组圆角 16 点；完成组直接使用画布 | 实际多行与空组渲染；检查完成项不与待办争抢注意力 |
| 标题承担主要阅读，列表只预览前三行，点开显示完整内容 | `titleMedium` / `textPrimary`；完整标题仍作为编辑按钮的辅助标签 | 中文 / 英文混排长标题、实际点开详情和编辑 |
| 进行中、已暂停、待继续保留明确文字，并辅以原生符号；状态用浅底深字 | `labelMedium`；`onTaskActiveContainer` / `taskActiveContainer`，`onTaskPausedContainer` / `taskPausedContainer` | 灰度仍可识别；按实际 RGB 测状态文字对比，不把鲜艳状态色直接作小字前景 |
| 已完成项置底、紧凑、删除线与完成符号；文字使用可读的次级色 | `textSecondary`；完成行上下 6 点，其他行上下 8 点 | 实际完成、恢复、撤销后位置与文案一致；必要信息不使用 `textTertiary` |
| 操作后的短时定位反馈不能让完成项重新成为主视觉 | 待办行用弱蓝背景，完成行用中性弱背景；撤销仍由原回执提供 | 完成 / 恢复后真实反馈与撤销，保留原反馈有效期 |
| 图标大小和可点击范围分开处理，列表内每个完成与编辑入口至少 44 点高 | 完成按钮 44×44；编辑按钮最小高度 44；分段与右下角新增沿用既有原生入口 | 实际点击、辅助点击区域、空输入禁用及取消；截图不代替交互结果 |
| 空列表直接在画布上说明下一步，不用大面积外框伪装内容 | 图标、标题、短说明居中；右下角新增是唯一创建入口 | 空输入保持禁用，取消后回到空态，填写后真实保存 |
| 列表完成符号保持 20 点，不随辅助字号撑破 44 点按钮 | 固定符号大小与完整点击区分别定义 | 辅助字号最大档的原生图、实际完成 / 撤销 |
| 底栏每项至少 44 点高；紧凑标签允许放大到 `.xxxLarge`，不挤成省略号 | `V2BottomNavigationBar`；SF Symbols、全称辅助标签、`caption2` 的最大展示档限定 | 五个真实切页与选中反馈；辅助字号最大档检查标签，保持原拖拽顺序规则 |
| 当前任务页的纸白配色与系统栏使用同一个浅色方案 | `V2TasksView.preferredColorScheme(.light)`；适用于四个任务视图及其原生浮层，不声称已实现深色主题 | 在系统 light / dark 两种外观下检查状态栏、底栏和任务页可读性 |

本轮新增两个状态前景角色，理由是原亮绿 / 亮橙小字在浅色表面上的对比不足。对比计算以 `V2Theme` 的实际 RGB 为准；色值计算、截图目视、真实交互分别记录，不能推导整个 App 无障碍通过。该文件沿用项目原 Markdown 规范，未声称通过 Google DESIGN.md 格式 lint。

## 2026-10-05 · 手机四处评审修订

- 今天的已完成行保持紧凑、次级文字和删除线，增加「已完成」文字提示；点开仍能恢复，不用鲜艳背景把完成项抬回主视觉。
- 树图的已完成叶节点和父节点都显示「已完成」与删除线，使用可读的中性文字；完成信号不与目标分支色混用。
- 当前 iOS 视觉基线是浅色纸白。`V2RootView` 明确使用浅色方案，让系统导航标题、列表、浮层和底栏随同一方案显示；尚未设计完整深色主题时，不允许固定浅色画布混入深色系统列表。
- 「更多插件」及其底栏编辑页使用 `canvas`、`surfaceRaised`、`textPrimary` / `textSecondary` 和同一主要操作色；模块图标为次级色，低频入口不以黑卡片或随机色块突出。编辑页明确说明 2–5 个入口、更多插件必选及满栏时先移除的限制，解释添加 / 移除的禁用状态。
- 展示根没有勾选符号、箭头按钮或选中反馈，只显示名称；真实任务节点保留详情、展开、聚焦、复位和右下角新增。结构和列表承担不同阅读任务，不增加重复的目录页。

验收对应今天的完成 / 恢复、更多插件实际打开及底栏编辑、树的真实节点操作与空态；在系统深色外观下检查原生纸白渲染，并用本次构建的新截图建立独立评审版本，保留旧图与批注。

## 2026-10-06 · 多色思维导图树

用户要求带可见节点与多个分支颜色，取代 22 号纯文字树。复用既有目标色组与系统字体，以原生 SwiftUI 定稿；业务关系、展示根和操作保持兼容。

| 规则 | 原生实现 | 检查方式 |
| --- | --- | --- |
| 结构由紧凑节点、细曲线和小连接点共同表达 | 节点浅底 / 细边线，基础高度 64 点、节点背景高 56 点；不回到 96 点大卡片 | 原生单根 / 多根，首屏层级与实际展开 |

| 字重区分根、分支、叶节点，长标题两行预览 | titleMedium / bodyMedium；全文由详情提供 | 中文、长标题与六层实际操作 |
