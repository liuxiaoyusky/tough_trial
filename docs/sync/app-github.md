# App GitHub 同步与 AI 冲突处理

入口：助手菜单 → GitHub 同步。

保存 owner/repository、分支、Markdown 路径与该仓库的 Contents 读写凭据。凭据按仓库存入本机 Keychain，不写入日程、快照或 Trace。保存配置不会联网，第一次点击“立即同步”才连接指定仓库。新路径可创建文件；已有不同文档身份的非空本地日程应先导入对应文件，空白新设备可采用云端已有文档身份。

共同基线、SHA、最近同步、失败类别、待同步标记和冲突的三份候选持久保存在领域快照中。网络失败后本地编辑继续保留，重启后可重新读取远端并重试。上传使用刚读取的 SHA，409 重读合并，首次创建竞态的 422 也会重新读取；不重复新增本地稳定 ID。普通无变化同步不提交新版本。

网络期间的本地新修改会在接收结果时再次合并，保留为待同步；不能用较旧的成功结果清除新修改。同字段并发修改保留基线、本地、远端；更新 metadata 时间戳不会单独制造一个无意义的内容冲突。

## 自动同步范围

首次用户发起连接后，默认在 App 前台自动同步，可关闭。每 5 秒检查是否有待上传的新内容，空闲时约每 30 秒拉取一次；网络或服务器失败至少间隔 30 秒重试。凭据错误、文档错误、待确认方案和未解决冲突停止自动重试。退出前台会取消循环；不声明 iOS 后台持续运行能力。

只保存配置而未发起连接时，不自动上传。运行中的同步不会再并发启动第二轮；变更目的地后，旧请求结果不能写入新配置的日程。

## 本机发起 AI 冲突处理

使用本机已配置的助手服务，由手机发起模型请求，不意味着模型一定在设备端运行。模型只收到列出的冲突候选、相关任务标题和用户补充要求，不包含 GitHub 凭据。

可判断时返回每个冲突的结构化选择：本地、远端、基线，或仅对标题/备注/正文合并文字。未列出的字段、重复 ID、过期冲突版本均被拒绝。已知执行事实仅允许保留原事实；日期和任务关系再次经过 Core 检查。

默认实际应用并高亮，提供“撤销本次处理”。开启日程“修改前确认”时展示具体前后内容，确认才应用，取消不写。处理结果与恢复版本同一次保存；随后以远端版本为基线再次同步。撤销保留后来的执行事实和无关变更。

两个时间或要求无法可靠判断时只显示具体问题。可在“补充你的处理要求”中回答，再按要求处理；不会把澄清当成写入成功。当前内容在模型处理中发生变化时拒绝迟到结果，下一次按最新内容重新处理。
