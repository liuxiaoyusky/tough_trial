# Obsidian Sync 调研与 Tough Trial 收费方向

调研日期：2026-09-14。依据官方公开文档；这是产品与架构研究，不代表本项目已经实现或验证这些能力。

## 1. 端到端加密

Obsidian 新建远端库默认提供 E2EE，也可选择由服务方管理密钥的标准加密。公开方案使用带盐 scrypt 派生密钥、AES-256-GCM 加密；E2EE 下服务方无法恢复加密密码。这个保护针对远端数据和传输，不会自动加密本地 vault。[官方安全说明](https://obsidian.md/help/sync/security)

官方同时披露了边界：部分设备、时间及加密路径与内容之间的映射元数据可被服务端读取；确定性加密哈希支持去重，但泄露一定的内容相等关系；路径和内容之间没有密码学绑定。不能把“服务端读不到正文”写成“没有任何元数据泄露或篡改风险”。[安全限制](https://obsidian.md/help/sync/security)

**本项目建议：**

- 使用成熟密码库；加密格式单独版本化，不自创密码算法。正式上线前做威胁建模、跨端测试向量和独立安全审查。
- 内容密钥与账号登录凭据分离；设备 Keychain 保存密钥，服务器只保存密文及必要索引。设计恢复码、可信设备迁移、密钥轮换和设备撤销；重设账号密码不能冒充恢复加密内容。
- 用认证附加数据绑定资料库 ID、对象 ID、版本和格式版本，校验完整性；另设回滚检测，AEAD 本身不阻止服务端重放旧的合法密文。
- 本地数据保护另行设计。GitHub 私有仓库、HTTPS 和 Base64 都不能称为 E2EE。
- 现有 GitHub Actions AI 运行器不能解密 E2EE 备份。不把解密密钥放进仓库或 Actions Secrets；用户主动调用云端 AI 时，仅发送该次授权的必要明文，另行说明接收方。

## 2. 冲突处理

Obsidian 对 Markdown 使用 diff-match-patch 合并；普通非 Markdown 文件采用最后修改者覆盖；设置 JSON 将本地键叠加在远端上。自 1.9.7 起可选择自动合并或创建冲突副本，此设置需要逐设备配置。自动合并仍可能产生重复文字或格式问题。[官方冲突处理](https://obsidian.md/help/sync/troubleshoot)

**本项目建议：**

- 已有日程三方语义合并继续使用稳定 ID 和共同基线。不同对象、互不影响的字段可自动合并；同一字段的并发修改保留双方。
- 账单金额、币种、发生日期、分类和付款状态作为有关联的业务字段处理，不能逐字段拼出双方都没有确认过的账单，也不能依据设备时钟静默覆盖。
- 财务冲突展示两个候选，由用户确认；AI 可以解释差异，不替用户确认分类或付款。现有日程冲突 AI 的权限不扩大到财务。
- 执行证据、付款事件按 ID 去重；删除采用带版本的删除记录，区分“未下载”“被排除”“明确删除”。
- 多渠道备份只是向多个目的地保存同一版本；不让 GitHub、WebDAV、NAS 同时成为同一资料库的双向写入源。

## 3. 版本恢复

Obsidian 支持查看差异、恢复笔记和已删除文件、恢复设置。笔记历史 Standard 保留 1 个月，Plus 保留 12 个月；附件旧版本保留 2 周。本地 File recovery 与远端 Sync 历史是两套机制。[版本历史](https://obsidian.md/help/sync/version-history)

**本项目建议：**

- 基础备份必须能恢复，不能只完成上传。先展示时间、来源设备、覆盖范围、对象数量和缺失附件，再选择恢复。
- 恢复前生成本地保护副本；所有数据与附件校验、迁移完成后才切换；失败不修改正在使用的数据。
- 恢复不重放待发送通知、AI 请求、付款或同步 outbox，不继承其他设备的文件授权书签和凭据。
- 高级恢复可以收费：更长历史、跨设备版本对比、批量恢复、恢复演练。但基础备份的完整性校验和基本恢复不是付费门槛。

## 4. 选择性同步

Obsidian 可按附件类型、目录和设置类别选择同步；同步设置本身不跨设备同步。一些设置变更需重启。排除已经上传的文件不会从远端自动删除，隐藏目录通常不参与同步（配置目录例外）。[选择性同步](https://obsidian.md/help/sync/settings)

**本项目建议：**

- 用户以任务、账本、笔记、助手会话、附件类别理解范围，不要求操作内部目录或 JSON 字段。
- 首次连接先展示本次范围，再上传；以后默认沿用已确认范围，新增敏感领域不自动扩张授权。
- “仅本机”“参与同步但附件按需下载”“彻底删除远端副本”是不同操作，不混为一个开关。
- 保留跨模块引用关系；未下载附件显示可下载状态，不能把空内容写回远端。

## 5. 运行与容量限制

官方 FAQ 明确：普通客户端只有在 Obsidian 运行时才同步，不提供退出后持续同步保证，也不建议把另一套双向同步同时作用于同一 vault。另有付费订阅可用的 Headless Sync（公开 beta），支持命令行单次或持续运行；仍需要运行中的进程，官方提醒不要在同一设备同时使用桌面 Sync 和 Headless Sync。[运行限制](https://obsidian.md/help/sync/faq)、[Headless Sync](https://obsidian.md/help/sync/headless)

历史与附件占用容量；超额会停止同步。Standard 为 1 库 / 1 GB / 单文件 5 MB，Plus 为 10 库 / 10 GB 起 / 单文件 200 MB，可增购至 100 GB，均不限设备数。[套餐与存储限制](https://obsidian.md/help/sync/plans)

**本项目建议：**

- 首期承诺前台手动备份和失败后可重试；后续自动触发需清楚显示“已在本机保存 / 等待上传 / 已校验备份”。
- iOS 后台机会受系统调度约束，付费不能突破系统限制；后台传输、前台恢复重试分别实现和真机验证。[Apple 后台策略](https://developer.apple.com/documentation/backgroundtasks/choosing-background-strategies-for-your-app)
- 后期 NAS / 自有常开设备可以运行客户端，但不能保证手机未上传的数据已进入备份。
- 容量、历史保留期、单附件大小、同步频率、设备状态和服务中断行为应公开；超额或订阅到期均不影响本地编辑和导出。

## 6. 收费建议：出售省心的托管服务

Obsidian 当前 Standard 年付折合 $4/月、月付 $5；Plus 年付折合 $8/月、月付 $10。这是对照信息，不是 Tough Trial 的定价。[官方价格](https://obsidian.md/sync)

| 层级（建议，未定价） | 用户得到的价值 | 边界 |
| --- | --- | --- |
| 本地与自有存储基础能力 | 离线使用、标准导出、GitHub 备份及基本恢复 | 用户提供自己的存储；现阶段只实施 GitHub |
| 后续自有存储渠道 | WebDAV；通过 WebDAV 访问 NAS，必要时另做 NAS 协议适配 | 共用备份格式，不能把 NAS 当成一种统一协议 |
| 托管 Sync 订阅 | 默认 E2EE、免配置跨端同步、设备管理、同步健康提示、基础历史 | 以存储、带宽、可靠性和运维服务收费；不是把安全做成高价专属 |
| 高级恢复与容量 | 更长历史、更大附件、更多空间、跨设备差异和批量恢复 | 分层保留期须明确区分正文与附件；价格在成本与用户验证后确定 |

取消订阅应保留本地数据、导出和自有渠道能力；建议提供可见的远端保留宽限期与提醒，具体期限在服务发布前确定。Obsidian 自身的到期政策是远端保留一个月、本地不受影响。[到期政策](https://obsidian.md/help/sync/faq)

收费前的必要证据：两个独立设备离线编辑再汇合；财务冲突无静默丢失；丢失设备后的密钥恢复；损坏/缺附件恢复失败仍保全本地；中断和超额可恢复；订阅到期能导出；Android/iOS/Web 互通。当前项目只有原生 iOS 客户端，跨端客户端与协议兼容性需要独立开发，不能作为已有能力售卖。

## 结论与完成边界

用户已确认本地优先、多渠道备份、首期只开发 GitHub；WebDAV/NAS 保留扩展方向。本文完成了五项官方机制调研和收费方向分析。具体方案见[本地备份与同步设计](../superpowers/specs/2026-09-14-local-backup-and-sync-design-zh.md)。E2EE、全领域双向同步与商业订阅均未实现；本次没有创建订阅、修改收费或上传个人数据。
