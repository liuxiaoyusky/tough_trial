# App 日程文件

入口：助手右上角菜单 → 日程文件。

- 选择并读取已有文件：通过系统文件选择器读取 Markdown，与当前日程合并后绑定。文件路径授权 bookmark、读取基线、任务变化和恢复记录同一次保存到本机快照。
- 导出为新文件：通过系统保存面板导出当前日程，成功后绑定该文件。
- 重新读取：合并手机与文件自上次基线以来的修改。
- 合并并写回：先读最新文件再合并，写入前再次比较文件原始内容；检测到其他编辑时停止覆盖。写入期间 App 有新更改，仍保留在本地作为待写回内容。
- 恢复记录：保留最近 20 次文件变更的前后内容。恢复只撤回所选变更涉及的任务、分类、排期与正文；保留无关任务、执行记录和云端请求。相关任务后来有编辑或新执行依赖时停止恢复。恢复本身也产生一条记录，可再恢复。

文件格式错误、重复条目、失效引用或语义冲突时不替换当前日程。保存失败时内存与磁盘不会只更新一半。所有时间与请求保留使用协议中的时区、稳定身份，不以标题匹配来重建任务。

文件模式目前由用户主动读取/写回，界面显示是否有本地内容待写回；不声称已实现后台 GitHub 自动同步。GitHub 配置、持久重试状态与本机 AI 冲突处理已有实现，见 [App GitHub 同步](app-github.md)；真实远端联调尚未完成。

文件操作的使用记录包含操作 ID 与耗时。读取/合并产生变更时，Trace 的 `operationID` 与恢复记录的变更 ID 一致；恢复事件标记为撤销并引用被恢复的变更。成功与失败均不记录任务正文、文件名、路径或原始错误内容。无内容变化的读写仍有独立操作 ID，但不会新增恢复版本。

已验证：本机核心原子导入/失败/恢复/重启、模拟器 App 文件往返及并发保护、系统文件选择器打开与取消。完整 UI 测试还覆盖：读取外部改动→助手新增任务→写回→恢复原始本地快照后重新读取文件→恢复此前内容→再次重启验证。该测试使用隔离临时文件与确定性助手，不能代替真实模型验收。跨 App 文件提供者、iCloud 下载与真机 bookmark 重启授权仍需要真机验收。
